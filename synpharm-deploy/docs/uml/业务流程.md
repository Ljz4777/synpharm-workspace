## 3. 单条预测业务流程 ✅

DTI / PPI / DDI 三算法，含**三段管道**（解析器 → 执行器 → 格式化器）、外部引用解析与熔断降级。

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant FE as 前端 Predict.vue
  participant C as PredictController
  participant S as PredictService
  participant PF as DataPipelineFactory
  participant RS as InputResolver
  participant RD as Redis 缓存
  participant EXT as UniProt / RCSB
  participant F as FastApiClient + 熔断器
  participant FA as FastAPI 算法引擎
  participant DB as MySQL

  U->>FE: 选择算法与输入类型
  Note over FE,C: DDI 额外先取药物白名单（转导式模型的能力边界）
  FE->>C: GET /api/predict/ddi/drugs
  C->>FA: GET /v1/ddi/drugs
  FA-->>C: 药物列表 + 图规模
  C-->>FE: 提前排除不在图内的药物

  U->>FE: 填写输入并提交
  FE->>C: POST /api/predict/general
  C->>C: 参数校验（语法级）
  C->>S: predict(request, userId)

  rect rgb(235,245,255)
  Note over S,PF: 第一段 · 输入解析
  S->>PF: process(inputType, algoType, outputType, value)
  PF->>PF: 按 InputType 选择解析器（策略模式）
  end

  rect rgb(235,255,240)
  Note over PF,EXT: 第二段前置 · 外部引用解析（仅引用型输入）
  alt 输入是 UniProt / PDB 引用
    PF->>RS: resolve(reference)
    RS->>RD: GET 缓存
    alt 缓存未命中
      RS->>EXT: GET rest.uniprot.org / data.rcsb.org
      EXT-->>RS: 元数据 + 序列 / 结构
      RS->>RD: SET 正缓存 24h（失败写负缓存 10min）
    end
    RS->>RS: 校验字符合法性 + 序列长度 ≥ 31 残基
    alt 校验失败
      RS-->>PF: 400 SEQUENCE_TOO_SHORT / INVALID_SEQUENCE
    end
  end
  end

  rect rgb(255,245,235)
  Note over PF,FA: 第二段 · 算法执行
  PF->>F: predictSingle(request)
  F->>F: 熔断器状态检查
  alt 熔断器已打开
    F-->>PF: 503 FASTAPI_UNAVAILABLE（快速失败）
  else 熔断器闭合
    F->>FA: POST /v1/predict/single
    FA->>FA: 路由 → 算法 Service → 模型推理
    alt 推理成功
      FA-->>F: 亲和力 / 置信度 / 相互作用残基
    else 引擎可达但推理失败
      FA-->>F: 错误体 + MODEL_UNAVAILABLE / DRUG_NOT_SUPPORTED
    end
    Note over F: 累计失败达阈值则熔断 30 秒
  end
  end

  rect rgb(245,240,255)
  Note over PF,DB: 第三段 · 格式化与落库
  PF->>PF: OutputFormatter（Json / Csv）
  S->>DB: INSERT predict_task + predict_result
  Note over S,DB: 外部 HTTP 必须在事务外<br/>单条预测事务持有小于 100ms<br/>落库失败不得静默
  end

  S-->>C: PredictResultResponse
  C-->>FE: 200 结果
  FE-->>U: 展示亲和力 / 置信度 / 相互作用
```

## 4. 批量预测业务流程 ✅

CSV 上传 → 202 受理 → RabbitMQ → 分片消费 → 进度 → 下载，含失败重试 / 死信 / 重启自愈。

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant FE as 前端
  participant C as BatchUploadController
  participant S as BatchProcessService
  participant PR as BatchTaskProducer
  participant MQ as RabbitMQ
  participant K as BatchTaskConsumer
  participant DB as MySQL
  participant RD as Redis
  participant PF as DataPipelineFactory
  participant FA as FastAPI

  U->>FE: 选择算法 + 上传 CSV
  FE->>C: POST /api/batch/upload（multipart）
  C->>C: 文件校验（类型白名单 + 大小 ≤ 100MB）
  C->>S: uploadBatch(file, algoType, userId)
  S->>S: 保存文件 + 统计行数
  S->>DB: INSERT batch_task（PENDING）
  S->>RD: SET 进度初值
  S->>PR: publish(batchId, algoType)
  Note over S,PR: 投递必须在 afterCommit<br/>否则消费者会读到不存在的任务
  PR->>MQ: 持久化消息 → batch.task.queue
  S-->>C: batchId + PENDING
  C-->>FE: 200 等待队列

  rect rgb(255,245,235)
  Note over MQ,K: 异步消费
  MQ->>K: 投递消息
  K->>DB: 幂等前置：非 PENDING 则直接 ack 跳过
  K->>DB: UPDATE status = PROCESSING
  end

  loop 按 CHUNK_SIZE = 50 分片
    K->>PF: batchProcess(chunk)
    PF->>FA: POST /v1/predict/batch
    alt 该片成功
      FA-->>PF: 批量结果
      PF-->>K: 格式化后的结果
      K->>DB: 每片独立事务：INSERT batch_task_item<br/>UPDATE 进度与计数
      K->>RD: SET 进度
    else 该片失败（超时 / 引擎不可用）
      K->>DB: 记录失败明细<br/>不得把 PARTIAL 上报为 SUCCEEDED
    end
  end

  rect rgb(235,255,240)
  Note over K,DB: 落终态
  K->>K: 汇总成功结果 → 写出结果 CSV
  K->>DB: UPDATE status = SUCCEEDED / PARTIAL / FAILED<br/>result_path + progress = 100
  K->>RD: SET 终态进度（TTL 24h）
  K->>MQ: basicAck
  Note over DB: 状态以 DB 为权威<br/>Redis 过期或重启后仍可正确查询
  end

  rect rgb(255,235,235)
  Note over MQ,K: 失败隔离与有限重试
  K->>MQ: basicNack(requeue = false)
  MQ->>MQ: 死信路由 → batch.task.dlq
  Note over MQ: 死信队列有消息必须告警<br/>不得静默堆积<br/>补偿任务扫描重试，上限 3 次
  end

  loop 每 2 秒，直到终态
    FE->>C: GET /api/batch/status/batchId
    C->>S: getBatchStatus(batchId, userId)
    Note over S: 归属校验 batchId + userId，防 IDOR
    S->>RD: 优先读缓存
    alt 缓存 miss
      S->>DB: 回查 batch_task
    end
    S-->>FE: status + progress + 成功/失败计数
  end

  U->>FE: 查看明细 / 下载结果
  FE->>C: GET /api/batch/batchId/items
  C-->>FE: 逐条成功失败 + 错误码
  FE->>C: GET /api/batch/download/batchId
  C->>S: downloadBatch（归属校验，非终态返回 409）
  S-->>FE: 结果 CSV 流
```

## 5. 批量任务状态机

### 5.1 当前实现（`batch_task.status` TINYINT 0~3）

```mermaid
stateDiagram-v2
  direction LR
  [*] --> PENDING0: POST /api/batch/upload<br/>写库 + 投递 MQ
  PENDING0 --> PROCESSING1: 消费者认领<br/>先校验非 PENDING
  PROCESSING1 --> SUCCESS2: 全部片成功<br/>生成结果 CSV
  PROCESSING1 --> FAIL3: 片失败 / 引擎不可用<br/>重试耗尽
  FAIL3 --> PENDING0: 补偿任务重新入队<br/>retry_count 小于 3
  SUCCESS2 --> [*]
  FAIL3 --> [*]
  PENDING0: PENDING(0) 已上传落库
  PROCESSING1: PROCESSING(1) 消费者已认领
  SUCCESS2: SUCCESS(2) 完成，有 result_url
  FAIL3: FAIL(3) 异常，可补偿重试
```

**现状 5 个缺陷**（源自 [`../modules/predict/批量处理技术设计文档.md`](../modules/predict/批量处理技术设计文档.md) §2.2）

| # | 缺陷 | 影响 |
|---|---|---|
| P1 | 表缺 `deleted` 列但 Mapper 有 `AND deleted=0` | `status`/`download` 在 Redis 过期后必报 SQL 错 |
| P2 | 表缺 `algo_type` 列 | 只能依赖 Redis 才知道算法类型 |
| P3 | 状态与进度以 Redis 为准 | 服务重启即丢 |
| P4 | `status`/`download` 不校验归属 | IDOR |
| P5 | 线程池任务重启即丢 | 无持久化 |
| **另** | **缺 `PARTIAL` 态** | 部分片失败时会把"部分成功"上报为成功 |

### 5.2 目标统一字典（与设计域 `design_job` 合并为全域唯一）

```mermaid
stateDiagram-v2
  direction LR
  [*] --> PENDING: 受理（202 + jobNo）
  PENDING --> RUNNING: 消费者认领
  PENDING --> CANCELLED: 取消（未开始）
  RUNNING --> SUCCEEDED: 全部成功
  RUNNING --> PARTIAL: 部分片 / 部分指标失败<br/>必须逐项写明原因
  RUNNING --> FAILED: 致命错误 / 重试耗尽
  RUNNING --> CANCELLED: 取消
  SUCCEEDED --> [*]
  PARTIAL --> [*]
  FAILED --> [*]
  CANCELLED --> [*]
```

**迁移映射**

| 现状 `batch_task` | 目标统一字典 | 说明 |
|---|---|---|
| `PENDING(0)` | `PENDING` | 语义不变 |
| `PROCESSING(1)` | `RUNNING` | 更名，与 `design_job` 一致 |
| `SUCCESS(2)` | `SUCCEEDED` | 更名（**注意不是 `SUCCESS`**） |
| `FAIL(3)` | `FAILED` | 更名 |
| 无 | `PARTIAL` | **新增**：部分成功必须可见 |
| 无 | `CANCELLED` | **新增**：支持取消 |

> DB 由 `TINYINT` 改为 `VARCHAR(24)`，一次性 UPDATE 映射旧值；`batch_task` 与 `design_job` 共用 `synpharm-common` 中的同一套状态常量。

| 咬合点 | 说明 |
|---|---|
| **★ 活性维度** | 设计域的「活性」指标**不重写模型**，而是复用预测域的三模型，按 `targetRole` 分别调用以支持选择性指数 |
| **★ 回灌校准** | 校准**不直接改模型权重文件**，而是产出**版本化校准工件**（残差 / Isotonic），可回滚、可审计 |

```mermaid
  Note over FE,GW: 公共前置 · 网关统一入口
  U->>FE: 操作
  FE->>GW: ANY /api/** + Authorization + Idempotency-Key
  GW->>GW: CORS 白名单（仅网关配置）
  GW->>GW: JWT 校验：验签 + iss/aud/exp/jti<br/>不只看签名
  GW->>GW: 查 token 黑名单
  alt Token 失效
    GW-->>FE: 401 UNAUTHORIZED
  else 通过
    GW->>GW: 剥离伪造的 X-User-*，写入可信身份头
    GW->>GW: 限流（IP + 用户 + 路径）
  end
  end

  rect rgb(255,245,235)
  Note over GW,FA: 场景 A · 设计域写路径（提交生成）
  GW->>DS: POST /api/design/projects/id/generation-jobs
  DS->>DS: 归属校验 fail-closed → 404
  DS->>PL: GET /internal/tools/capabilities
  PL-->>DS: 工具可用性 + probeMsg
  alt 所选策略不可用
    DS-->>FE: 409 COMMAND_UNAVAILABLE<br/>点击前即置灰
  end
  DS->>DS: 幂等键解析
  alt 命中既有 job
    DS-->>FE: 200 reused = true
  else 新任务
    DS->>DBD: 事务内只写本地：<br/>INSERT design_job + generation_run
    DS->>MQ: afterCommit 投递
    DS-->>FE: 202 + jobId + jobNo
  end
  MQ->>DS: 消费
  DS->>FA: POST /v1/generate（事务外）
  loop 分批返回候选
    FA-->>DS: 一批候选
    DS->>AST: 登记文件引用计数
    DS->>DBD: 每批独立事务 + 唯一键去重
    DS-->>FE: SSE 推送增量候选
  end
  DS->>DBD: UPDATE 终态（SUCCEEDED / PARTIAL / FAILED）
  end

  rect rgb(235,250,240)
  Note over GW,FA: 场景 B · 预测域写路径（提交批量预测）
  GW->>PS: POST /api/batch/upload
  PS->>AST: 上传文件资产
  PS->>DBP: INSERT batch_task（只写自己的 schema）
  PS->>MQ: afterCommit 投递
  PS-->>FE: 200 batchId
  MQ->>PS: 消费
  PS->>DBP: UPDATE status = RUNNING
  loop 每片 50 条
    PS->>FA: POST /v1/predict/batch（不重试）
    PS->>DBP: 每片独立事务 + 进度
  end
  PS->>AST: 结果 CSV 落对象存储
  end

  PS-->>FE: 轮询进度（DB 为权威）
```

**目标态四条关键约束**

| # | 约束 |
|---|---|
| 1 | 网关是**唯一**对外入口，也是**唯一** CORS 与 JWT 校验点 |
| 2 | 服务端口不映射宿主；`/internal/**` 网关不路由（需 `X-Internal-Token`） |
| 3 | 服务各写自己的 schema；跨服务**只读走 Feign、写走事件或 owner 接口** |
| 4 | 计算层在网格外，仅 `/v1/**` + `X-API-Key` |

## 8. 贯穿全部流程的 8 条红线

| 红线 | 内容 |
|---|---|
| R1 | **能力与真实性可见**：未部署引擎点击前置灰；部分失败逐项说明 |
| R2 | **能力事实单一权威**：`design_tool.available` 只由探测回写 |
| R3 | **一切计算在 FastAPI**，且 FastAPI 不碰数据库 |
| R4 | **归属校验 fail-closed**，归属不符一律 404 |
| R5 | **事务边界**：事务内只本地写、MQ `afterCommit`、批量独立事务 |
| R6 | **长任务可取消、可观测、可恢复**（DB 为权威，Redis 只是投影） |
| R7 | **幂等**：写操作可重放不产生副作用 |
| R8 | **禁止静默兜底**：看似正常但无意义的算法结果必须记 `success = 0` |
