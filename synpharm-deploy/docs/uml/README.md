## 3. Mermaid 写作注意（实测踩过的坑）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | `flowchart` 节点标签里写**直引号** | 用中文引号 `「」`；`A[提示"错误"]` 会解析失败 |
| 2 | `flowchart` 边标签写成 `A --> B: 说明` | 必须用 `A -->|说明| B` |
| 3 | `|边标签|` 里含**圆括号** | 去掉或换成逗号；`|6. POST /x (JSON)|` 会失败 |
| 4 | `erDiagram` 实体块里写 `<<构造型>>` | **不支持**（`classDiagram` 支持）。改用图外的说明表 |
| 5 | `stateDiagram` 转移指向带引号的裸状态名 | 先 `state "长名" as 别名`，转移里只写别名 |
| 6 | `sequenceDiagram` 用 `cloud` 关键字 | 不支持（属组件图），用 `participant` |

**校验方法**：用 `mermaid` 官方解析器逐块 `await mermaid.parse(code)`（本项目已建立该校验流程，**当前 61/61 块全部通过**）。

## 4. 历史勘误：上游 A-7 / R-16 判断有误

[`../design/detailed/00-设计评审与勘误.md`](../design/detailed/00-设计评审与勘误.md) 的 **R-16** 与 [`../design/detailed/README.md`](../design/detailed/README.md) 的待决策项 **A-7** 判定 `02-component.puml` / `07-activity.puml`「**无法渲染**，建议**重写**」。**该判断是错的，无需重写。**

| 项 | 实际情况 |
|---|---|
| 图的内容与语法 | **完全正确**（现已在 [`设计域.md` §2](./设计域.md#2-设计域组件与依赖) / [`§7`](./设计域.md#7-端到端活动图) 内正常渲染） |
| 失败原因 | **渲染命令未指定 UTF-8 字符集**，不是图有问题 |
| 上游已排除的假设 | 上游已正确排除「文件缺 BOM」（13 个文件全无 BOM 却有 11 个通过） |
| 遗漏的一环 | 未考虑**调用时字符集**：`-checkonly` / 渲染若不带 `-charset UTF-8`，PlantUML 会按 GBK 猜测编码，对部分内容猜错 → 中文被误读成语法字符 |

**6 组对照实测**（同一文件 `02-component.puml`、同一内容）

| 组合 | `-checkonly` | 真实渲染 |
|---|---|---|
| 无 BOM，无 `-charset` | `200` ❌ | `200` ❌ |
| 无 BOM，`-charset UTF-8` | `0` ✅ | `0` ✅ |
| 有 BOM，无 `-charset` | `0` ✅ | `0` ✅ |

> 结论：**加 BOM** 与 **传 `-charset UTF-8`** 两种解法等价。这是本项目 PlantUML 阶段的唯一真实障碍，与图的设计无关。
> 现全部改为 Mermaid 内嵌后，该问题**已彻底消失**（Mermaid 由渲染器按 UTF-8 处理，无字符集猜测环节）。
