## 4. 主链路时序（立项 → 生成 → 编辑 → 评估 → 报告 → 审批）

```mermaid
sequenceDiagram
  autonumber
  actor U as 科学家
  participant FE as 前端工作台
  participant C as Controller
  participant S as Service 编排
  participant JOB as DesignJobService
  participant DB as MySQL
  participant MQ as RabbitMQ
  participant W as DesignTaskConsumer
  participant FA as FastAPI

  Note over U,FA: ① 立项
  U->>FE: 新建项目
  FE->>C: POST /api/design/projects
  C->>S: createProject(dto)
  S->>DB: INSERT design_project DRAFT + project_target + constraint_set
  S->>FA: POST /v1/targets/resolve（权威元数据与序列补全）
  FA-->>S: name + sequence + pdbIds
  S->>DB: 重算 READY（有靶点 且 有 ACTIVE 约束集）
  S-->>FE: 200 projectId + status READY

  Note over U,FA: ② 生成（异步 202）
  U->>FE: 选策略提交生成
  FE->>C: POST /projects/id/generation-jobs
  C->>S: submitGeneration(dto)
  S->>JOB: create(jobType=GENERATION, idempotentKey)
  JOB->>DB: INSERT design_job PENDING
  S->>DB: INSERT generation_run PENDING
  S->>MQ: afterCommit 投递 design.generate
  S-->>FE: 202 jobId + jobNo
  MQ->>W: 消费
  W->>DB: UPDATE design_job RUNNING
  W->>FA: POST /v1/generate
  loop 分批返回候选
    FA-->>W: 一批候选 + 统计
    W->>DB: 每批独立事务 INSERT candidate_molecule
    W->>DB: 更新 progress 与 done_count
    W-->>FE: SSE 推送增量候选
  end
  W->>DB: UPDATE generation_run 与 design_job 终态

  Note over U,FA: ③ 编辑（同步，保存即编译）
  U->>FE: 画布加一个羟基
  FE->>C: POST /candidates/id/edits
  C->>S: edit(dto)
  S->>FA: POST /v1/molecules/edit
  FA-->>S: childSmiles + childInchikey + changedAtoms
  alt 产物已存在
    S-->>FE: 409 MOLECULE_DUPLICATED existingId
  else 新产物
    S->>DB: INSERT candidate_molecule EDITED + molecule_edit_log
    S->>FA: POST /v1/evaluate/describe（同步快评，目标小于 1.5s）
    FA-->>S: 该分子全量轻指标
    S->>DB: INSERT evaluation_result scope=INCREMENTAL
    S-->>FE: 200 metrics + constraintRAG
  end

  Note over U,FA: ④ 评估（批量加权打分）
  U->>FE: 一键评估全部候选
  FE->>C: POST /api/design/evaluations
  C->>S: submitEvaluation(dto, currentUser)
  S->>DB: 校验归属，失败返回 404
  S->>DB: INSERT evaluation_run PENDING + design_job PENDING
```

## 6. 五个状态机

### 6.1 项目 `design_project`

```mermaid
stateDiagram-v2
  direction LR
  [*] --> DRAFT : 新建项目
  DRAFT --> READY : 绑定靶点 且 激活约束集（READY 为推导态，非手置）
  READY --> DRAFT : 解绑靶点 / 约束集失效
  READY --> ACTIVE : 开启第一轮
  ACTIVE --> ACTIVE : 轮次 CLOSED 后开下一轮
  ACTIVE --> COMPLETED : 选定最终候选集（报告 APPROVED）
  ACTIVE --> CANCELLED : 用户取消
  COMPLETED --> ARCHIVED : 归档
  CANCELLED --> ARCHIVED : 归档
  ARCHIVED --> [*]
```

### 6.2 轮次 `design_round`

```mermaid
stateDiagram-v2
  direction LR
  [*] --> PLANNED : openRound()
  PLANNED --> GENERATING : 启动 generation_run
  GENERATING --> EDITING : 生成完成
  GENERATING --> EVALUATING : 跳过编辑
  EDITING --> EVALUATING : 手工微调结束
  EVALUATING --> REVIEWING : 评估完成
  REVIEWING --> GENERATING : 结论不足，同轮重生成
  REVIEWING --> CLOSED : 记录结论并关闭
  CLOSED --> [*]
```

### 6.3 统一任务 `design_job`

```mermaid
stateDiagram-v2
  direction LR
  [*] --> PENDING : 提交（202 + jobNo）
  PENDING --> RUNNING : 消费者认领
  PENDING --> CANCELLED : 取消（未开始）
  RUNNING --> SUCCEEDED : 全部成功
  RUNNING --> PARTIAL : 部分指标/策略失败（如 vina 未装）
  RUNNING --> FAILED : 致命错误 / 重试耗尽
  RUNNING --> CANCELLED : 取消
  SUCCEEDED --> [*]
  PARTIAL --> [*]
  FAILED --> [*]
  CANCELLED --> [*]
```

> **枚举映射**：需求 `jobs.status` 为 `pending/running/succeeded/failed/cancelled`；本设计为 **6 态**，在上表基础上**新增 `PARTIAL`** —— 生成/评估存在"部分成功"（多指标、多策略），强行归入 `SUCCEEDED` 会掩盖能力缺口。同时把既有 `generation_run` / `evaluation_run` 的 `SUCCESS` 统一更名为 `SUCCEEDED`，全域共用一个字典。

### 6.4 候选评审 `candidate_molecule.review_status`

```mermaid
stateDiagram-v2
  direction LR
  [*] --> NEW
  NEW --> REJECTED : 命中任一 HARD 约束
  NEW --> QUALIFIED : 综合得分达到 qualify 阈值
  QUALIFIED --> TOP : 综合得分达到 top 阈值
  QUALIFIED --> REJECTED : 人工否决
  TOP --> SELECTED : 进入报告送样清单
  SELECTED --> REJECTED : 湿实验失败
  REJECTED --> [*]
  SELECTED --> [*] : 结项
```

### 6.5 报告审批 `design_report.decision`

```mermaid
stateDiagram-v2
  direction LR
  [*] --> PENDING : 报告生成完成
  PENDING --> APPROVED : 审批通过 → 触发送样 + 可下一轮
  PENDING --> REVISE : 打回修订 → 生成 revision_of 新版本
  PENDING --> REJECTED : 驳回 → 可归档
  REVISE --> PENDING : 修订版重新提交

  REJECTED --> [*]
```

## 10. 编辑快车道时序（保存即编译）

```mermaid
sequenceDiagram
  autonumber
  actor U as 研究者
  participant FE as 前端画布
  participant C as EditController
  participant A as EditAppService
  participant FA as FastAPI /v1/molecules/edit
  participant FAP as FastAPI /v1/evaluate/properties
  participant DB as MySQL

  U->>FE: 拖动取代基 / 编辑原子
  FE->>FE: 本地乐观预览（不落库）
  U->>FE: 松开（或点应用）
  FE->>C: POST /candidates/id/edits（previewOnly=false, evaluateInline=true）
  C->>C: 参数校验 + assertOwnership（跨用户 → 404）

  alt previewOnly = true（画布实时预览，可高频）
    C->>A: preview(...)
    A->>FA: POST /v1/molecules/edit
    FA-->>A: childSmiles + changedAtoms + describe + warnings
    A-->>C: 组装 DTO（不落库）
    C-->>FE: 200 metrics 为空
  else 正式提交
    C->>A: execute(...)
    rect rgb(235,245,255)
    Note over A,DB: 事务 A（短事务：只做本地写）
    A->>DB: INSERT candidate_molecule origin_type=EDITED, parent_mol_id
    A->>DB: INSERT molecule_edit_log operator_type=USER
    end
    alt 产物已存在（唯一键 1062）
      DB-->>A: Duplicate entry
      A-->>C: 归一化为 MOLECULE_DUPLICATED + existingId
      C-->>FE: 409 existingId，询问是否跳转
    else 落库成功
      DB-->>A: candidateId
      rect rgb(235,252,240)
      Note over A,DB: 事务 B（另一个短事务：同步快评）
      A->>FAP: POST /v1/evaluate/properties
      FAP-->>A: metrics 数组（value, success, detail）
      A->>A: 约束求值（HARD 淘汰 / SOFT 扣分）+ 得分归一化
      A->>DB: UPSERT evaluation_result（uk_run_mol_metric 幂等）+ 回写 total_score
      end
      A-->>C: candidateId + metrics + constraintRag + totalScore
      C-->>FE: 201
      FE->>FE: 右栏指标与约束红黄绿刷新（小于 1.5s 手感）
      FE->>FE: 画布显示分叉（兄弟分支而非覆盖）
    end
  end
```

> **为什么拆两个事务**：事务 A 只写本地（毫秒级、锁范围小）；事务 B 含一次外部 HTTP（快评），若与 A 同事务，会在 HTTP 期间持有行锁（历史问题 D-05 的反模式）。
> **静默兜底识别（红线 R2）**：引擎返回"看似正常但无意义"的值（如置信度恒 0.5）必须记 `success=0`，不计入排序。
> 若 `evaluateInline=false`：事务 B 改投 MQ（牺牲手感换稳定性）。

## 12. 校准工件状态机

```mermaid
stateDiagram-v2
  direction LR
  [*] --> FITTING : POST /v1/feedback/calibrate
  FITTING --> FITTED : 拟合成功（样本量 ≥ 10）
  FITTING --> REJECTED : FEEDBACK_NO_SAMPLE（样本量 < 10）
  FITTED --> REGISTERED : 上传工件 + 登记 file_asset + 更新 wet_experiment.feedback_*
  REGISTERED --> APPLIED : POST /v1/feedback/apply（装载到引擎内存注册表）
  REGISTERED --> REGISTERED : 幂等重复 apply
  REGISTERED --> REJECTED : modelVersion 不匹配 CALIBRATION_MODEL_MISMATCH
  APPLIED --> ACTIVE : POST /v1/feedback/activate
  ACTIVE --> SUPERSEDED : 新版本激活（同 algorithm + metricCode + targetRole）
  SUPERSEDED --> ACTIVE : POST /v1/feedback/rollback
  SUPERSEDED --> [*] : LRU 淘汰（大于 20 版），工件本体仍在对象存储可重新装载
  REJECTED --> [*]
```

> **工件形态**：manifest（≤ 256 KB，可内联）+ 可选大参数文件（isotonic 断点等）。两者都以 sha256 内容寻址 → 天然去重、防篡改。`calibrationId` 是业务标识（可读、可回滚），`sha256` 是内容标识（去重、校验）。
> **应用索引**：`(algorithm, metricCode, targetRole)`；`targetRole = null` 作为"默认校准"，被具体角色校准覆盖。
> **失败保护**：样本量 < 10 拒绝拟合；无校准时引擎**不加任何修正**，并回传 `calibrationId: null`（不得静默套用旧校准）。

## 13. 校准回灌时序

```mermaid
sequenceDiagram
  autonumber
  actor U as 研究者
  participant FE as 前端
  participant BE as ExperimentAppService
  participant FA as FastAPI /feedback/*
  participant S3 as 对象存储
  participant DB as MySQL

  Note over U,DB: ① 回灌受理
  U->>FE: 选择已验证的实验记录，提交回灌
  FE->>BE: POST /experiments/feedback
  BE->>BE: 校验有效样本（error_delta 非空、result_status=SUCCEEDED）
  BE->>DB: INSERT design_job PENDING
  Note right of BE: MQ 投递放 afterCommit（红线 R5）
  BE-->>FE: 202 jobId + batchNo

  Note over U,DB: ② 拟合
  BE->>FA: POST /v1/feedback/calibrate
  activate FA
  Note right of FA: mode: RESIDUAL_FIT / ISOTONIC / PLATT / TEMPERATURE<br/>留出法 hold-out 20%<br/>返回 before/after 统计（MAE / R² / 命中率）
  FA-->>BE: manifest + 可选大参数
  alt manifest ≤ 256 KB 且无大参数，或引擎与后端共享卷
    BE->>FA: POST /v1/feedback/apply（内联 manifest）
  else 有大参数（isotonic 断点 / PLATT 曲线）
    BE->>S3: 上传大参数（内容寻址）
    BE->>DB: INSERT file_asset（sha256 + calibration 内容类型）
    BE->>FA: POST /v1/feedback/apply（calibrationId + artifactUri + artifactSha256）
    FA->>S3: 下载并校验 sha256
    Note right of S3: artifactUri 仅接受白名单前缀（本地校准目录 / s3 / 内网预签名域）→ 防 SSRF
  end
  deactivate FA

  Note over U,DB: ③ 登记与激活
  BE->>DB: UPDATE wet_experiment feedback_to_model=1 + feedback_batch + calibration_id
  BE->>FA: POST /v1/feedback/activate
  activate FA
  alt modelVersion 不匹配
    FA-->>BE: 409 CALIBRATION_MODEL_MISMATCH
  else 匹配
    FA-->>BE: calibrationId + status ACTIVE（保留最近 20 版，LRU）
  end
  deactivate FA

  Note over U,DB: ④ 可复现闭环
  U->>FE: 发起新的预测 / 评估
  FE->>BE: POST /evaluations/jobs
  BE->>FA: POST /v1/predict/single 或 /v1/evaluate/*
  FA-->>BE: metrics + calibration（calibrationId + appliedMetrics）
  BE->>DB: INSERT evaluation_result，detail_json.calibrationId 快照
  BE-->>FE: 结果（含所用校准版本）
```

> **三条保证**
> - **可复现**：同一 `(SMILES, target, modelVersion, calibrationId)` → 同一输出
> - **可审计**：报告引用某数值 → 可追到 `(evaluation_run, calibrationId, 引擎版本)`
> - **可回滚**：实测偏差变大 → `POST /v1/feedback/rollback`
>
> **不做的事**：不修改模型权重文件（2.7 GB 二进制、不可审计、不可回滚）。
