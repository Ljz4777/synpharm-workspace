## 1. 通用约定

| 约定 | 规定 | 与设计书的差异 |
|---|---|---|
| 对外前缀 | `/api/design/**` | 保持（D5：不采用需求的 `/api/v1`） |
| 计算层前缀 | `/v1/**`（仅服务间，需 `X-API-Key`） | 保持 |
| 认证 | 用户侧 `Authorization: Bearer <JWT>`；服务间 `X-API-Key` | 保持 |
| 内容类型 | 请求/响应 `application/json; charset=utf-8`；导出 `text/csv` / `chemical/x-mdl-sdfile` | 保持 |
| 分页 | 请求 `?page=1&pageSize=20`（`page` 从 1，`pageSize` ≤ 200 默认 20）<br>响应 `data.{list,total,page,pageSize,hasNext}` | 保持 |
| 排序 | `?sortBy=<白名单字段>&order=desc`；**白名单强校验，禁止拼进 ORDER BY** | 保持 |
| 异步写 | 耗时写操作返回 **202** + `{jobId, jobNo, status}`；轮询 `GET /api/design/jobs/{jobId}` | 保持 |
| 幂等 | 请求头 `Idempotency-Key`（或服务端按业务推导）；命中 `uk_idempotent_key` 返回**既有 job** | 保持 |
| 乐观锁 | 更新类接口支持请求体 `version` / `If-Match`，冲突 → `409 STALE_OBJECT` | 保持 |
| 长连接 | `GET /api/design/stream/{jobNo}` 为 SSE；轮询为降级兜底 | 保持 |
| 限流 | 生成 5/min、评估 10/min、只读 300/min（按 用户+接口）；超限 `429` | **本设计补充**：限流键含 `projectId`（防单项目刷爆） |

### 1.1 统一响应信封

沿用后端既有 `Result<T>`：

```jsonc
// 成功 200 / 201
{ "code": 0, "errorCode": null, "message": "ok", "data": { } }

// 失败（errorCode 即需求中的 code；data.details 即需求中的 details）
{ "code": 40401, "errorCode": "DESIGN_PROJECT_NOT_FOUND",
  "message": "项目不存在或不属于当前用户",
  "data": { "details": { "projectId": 1024 } } }

// 异步受理 202
{ "code": 0, "message": "accepted",
  "data": { "jobId": 8891, "jobNo": "J260101120001A7F3", "status": "PENDING" } }
```

> **`code` 数值规则**（本设计补充，便于前端分流与日志聚合）：
> `0` = 成功；`4xxxx` = 4xx（`401xx`/`404xx`/`409xx`/`429xx`）；`5xxxx` = 5xx。
> 前端**应以 `errorCode` 字符串为准**做分支，`code` 仅用于聚合统计。

### 1.2 分页与游标边界

| 场景 | 规则 |
|---|---|
| 普通列表 | 偏移分页（`page`/`pageSize`）；`pageSize > 200` → `VALIDATION_FAILED` |
| 排行榜（大偏页） | **必须**携带 `roundId`；偏页 > 1000 时返回 `409 USE_CURSOR`，改用 `?afterScore=<total_score>&afterId=<id>` 的键集分页 |
| SSE | 事件序号 `Last-Event-ID`；候选/指标事件支持 `?since=<eventId>` 复位 |

> 排行榜在 10 万行 `evaluation_result` 上 `OFFSET` 会退化（§8.2 要求翻页 P95 < 300ms），键集分页是达标前提。

## 2. 错误码总表

### 2.1 通用

| errorCode | HTTP | 语义 | 前端建议 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 未登录 / JWT 失效 | 跳登录（沿用既有 `request.ts` 的"token 比对"逻辑） |
| `FORBIDDEN` | 403 | 已登录但无权限（**仅用于非归属类**，如管理员接口） | 提示无权限 |
| `VALIDATION_FAILED` | 400 | 参数语法/必填校验失败 | 高亮字段（`data.details.fieldErrors`） |
| `RATE_LIMITED` | 429 | 触发限流 | 按 `Retry-After` 退避，禁用按钮 |
| `INTERNAL_ERROR` | 500 | 未预期异常（**不泄露堆栈**） | 通用错误提示 + 上报 |
| `DEPENDENCY_UNAVAILABLE` | 503 | 下游（FastAPI / 对象存储）不可用 | 提示"算法引擎不可用"，引导到能力面板 |
| `STALE_OBJECT` | 409 | 乐观锁冲突 | 提示"他人已修改"，拉取最新后重试 |

## 4. 关键端点契约（15 个）

### ① `POST /api/design/projects` — 创建项目（含约束）

- **同步**；`201`。
- 请求：`name` \| `goalText` \| `diseaseId` \| `modalityId` \| `targets[]{targetId,role,isPrimary}` \| `objectives[]{dimension,operator,threshold,unit,weight}` \| `constraintRules[]`
- 响应：`{ id, projectNo, status, readyBlockers[] }`
- **`readyBlockers`**（红线 R2）：显式列出进入 `READY` 还缺什么（如 `"尚未激活约束集"`、`"主靶点缺少序列"`）。**不得**静默就绪。
- 副作用：同一事务内建 `design_project` + `project_target` + （可选）内联 `constraint_set` + `constraint_rule`。
- 校验顺序：`name` 非空 → `modalityId` 属 `MODALITY` → `targets` 至少 1 且**恰好 1 个 `isPrimary=true`** → 命中主靶点唯一键前置校验（`DESIGN_PRIMARY_TARGET_EXISTS`）→ 目标维度属 8 大维度。

### ② `GET /api/design/library` — 知识库检索

- `category` / `parentId` / `keyword` / `enabled` + 分页。
- 响应项含 `meta`（由 `meta_json` 反序列化）。
- `keyword` 匹配 `code` / `name` / `name_en`；超过 3 字符走 `LIKE 'x%'`（利用 `uk_category_code` 前缀）。

### ③ `POST /api/design/projects/{id}/generation-jobs` — 提交生成（202）

- 请求：`roundId` \| `strategies[]` \| `strategyParams{}` \| `targetCount` \| `seed{type,pocketId?}` \| `idempotencyKey`
- 响应 `202`：`{ jobId, jobNo, status:"PENDING" }`
- 校验：`strategies` 非空（否则 `GENERATION_NO_STRATEGY`）→ 需种子的策略未给种子 → `GENERATION_SEED_REQUIRED` → 同轮次无运行中任务（`GENERATION_RUN_ALREADY_ACTIVE`）→ 限流 5/min。
- 事务：**只写** `design_job`（`PENDING`）+ `generation_run`（`PENDING`）；MQ 投递 **`afterCommit`**（R5）。
- 幂等：`idempotencyKey` 默认 = `prj{projectId}-round{roundId}-{strategies 排序后逗号连接}`；命中 `uk_idempotent_key` 且未终态 → **返回既有 job**（`200`，`data.reused=true`）。

### ④ `GET /api/design/jobs/{jobId}` — 任务状态

- `{jobId}` 接受数字 ID **或** `jobNo` 字符串（正则判定）。
- 响应含 `toolCode` / `realness`（从 `design_tool` 联查）与 `result`（轻量摘要）。
- `status=PARTIAL` 时 `errorMsg` 必须写明**逐项原因**（如"策略 FRAGMENT_RECOMMINE 超时，其余成功"）。

### ⑤ `POST /api/design/candidates/{id}/edits` — 执行编辑（同步）

- **同步**，`201`；目标 P95 < 1.5s（§8.2）。`previewOnly=true` 不落库；`evaluateInline=true` 触发同步快评。
- 请求：`strategyCode` \| `editType` \| `targetRegion` \| `params` \| `previewOnly` \| `evaluateInline`
- 响应：`{ candidateId, parentMolId, modalityCode, smiles|sequence, describe, changedAtoms[], totalScore, reviewStatus, metrics[], constraintRag[] }`
- 事务（R5）：**同事务**插 `candidate_molecule`（`origin_type=EDITED`）+ `molecule_edit_log`；**快评结果**在**另一个短事务**写 `evaluation_result`（避免长事务）。
- 冲突：产物 InChIKey 已存在 → `MOLECULE_DUPLICATED` + `existingId`（前端应提示"该编辑产物已存在，是否跳转？"）。

### ⑥ `POST /api/design/evaluations/jobs` — 批量评估（202）

- 请求：`projectId` \| `roundId` \| `scope`（`ALL`/`SELECTED`/`INCREMENTAL`）\| `candidateIds[]`（`SELECTED` 必填）\| `metrics[]` \| `metricWeights{}` \| `targetRoleScope[]`
- 响应 `202`：`{ jobId, status }`
- 权重要求：`metricWeights` 缺省时用 `metric_definition.weight`；**两种情况都要写入 `evaluation_run.metric_weights` 快照**。
- `available=false` 的指标：**拒绝**进入 `metrics[]`（返回 `EVALUATION_METRIC_UNAVAILABLE` 的 200 业务告警 + `redistributed[]`），**不得**静默按 0 分处理。

### ⑦ `GET /api/design/projects/{id}/leaderboard` — 排行榜

- 请求：`roundId`（**必填**）\| `sortBy` \| `order` \| 分页。
- 响应含三段**可复现性证据**：

| 字段 | 作用 |
|---|---|
| `metricColumns[]` | 前端动态列（含 `unit`/`better`/`weight`） |
| `weightsSnapshot{}` | 本次排序所用权重（与 `evaluation_run` 一致） |
| `redistributed[]` | **未参与计算的指标 + 原因 + 权重重分配去向**（红线 R1） |

- 每个候选带 `realness`、`riskLevel`、`unavailableMetrics[]`。

### ⑧ `POST /api/design/reports` — 生成报告（202）

- 请求：`projectId` \| `roundId` \| `evaluationRunId` \| `reportType` \| `topN` \| `includeLineage` \| `includeExperimentAccuracy`
- 响应 `202`：`{ reportId, jobId, status }`（**立即返回 `reportId`** 便于前端先跳转详情页轮询）
- 报告正文**强制**包含：能力边界声明（写 `capability_note`）+ 实测准确率（含样本量；样本量 0 写"未验证"）。

### ⑨ `PATCH /api/design/reports/{id}/decision` — 审批

| decision | 副作用（同事务） |
|---|---|
| `APPROVED` | 生成送样清单 + 预写 `wet_experiment(PLANNED)`；项目可进入 `COMPLETED` 或下一轮 |
| `REVISE` | 插修订版占位（`revision_of`、`version_no+1`），`note` **必填** |
| `REJECTED` | 项目可归档；`note` **必填** |

- 幂等：同一 `version_no` 重复决策 → `REPORT_ALREADY_DECIDED`。
- 响应含 `revision{reportId,reportNo,versionNo,status}`。

### ⑩ `POST /api/design/experiments` — 录入湿实验结果

- **同步**，`201`。`assayType` 必须已在 `design_library_item(category=ASSAY)` 注册。
- 服务端**计算** `errorDelta = resultNum - predictedValue`、按 `is_hit` 阈值判定 `isHit`（都不接受客户端传入）。
- **命中判定口径**（本节原先未定义阈值来源，阶段 2B 固定下来并由 `HitJudge` 单一实现）：由 `predicted_metric`
  查 `metric_definition` 得到**维度**，再取项目 `goal_metric_json` 中同维度的目标 `{operator, threshold}` 判定；
  缺任一环 → `isHit = null`（**不得写成 false**，否则污染下游命中率统计）。实测为有界值（`operator=GT/LT`，
  如 `>10000 nM`）时只给「可证伪」方向的结论，否则仍为 `null`。
- **已知数据限制**：`metric_definition` 目前 24 行中仅 7 行有 `dimension`（其余为 `MOL_WT`/`QED`/`SA_SCORE`
  等理化与 ADMET 描述符），这些指标的实验无法映射到优化目标，`isHit` 恒为 `null`。
- `operator` 支持不等式（如 `>10000 nM`）时，`resultNum` 存阈值、`resultText` 存原文。

### ⑪ `GET /api/design/projects/{id}/experiment-accuracy` — 实测准确率

- 响应 `byAssay[]{assayType,targetRole,sampleN,mae,hitRate,r2}` + `overall{}` + `note`。
- **`sampleN < 30` 必须在 `note` 中提示统计置信度有限**，且报告正文引用同一口径。
- `sampleN = 0` → 各指标返回 `null` 并 `note: "未验证"`。

### ⑫ `POST /api/design/experiments/feedback` — 回灌校准（202）

- 请求：`projectId` \| `experimentIds[]` \| `mode` \| `note`
- 响应 `202`：`{ jobId, status, batchNo }`
- **不直接改模型权重文件**，产出**版本化校准工件** `calibrationId`（协议见 [`04-计算层契约与校准协议.md`](./04-计算层契约与校准协议.md) §4）。
- 前置：有效实测样本数 = 0 → `FEEDBACK_NO_SAMPLE`。

### ⑬ `POST /api/design/projects/{id}/next-round` — 启动下一轮（202）

- 请求：`strategyNote` \| `seedFrom` \| `calibrationId` \| `autoStartGeneration` \| `generation{...}`
- 响应 `202`：`{ roundId, roundNo, jobId, status }`
- 副作用：关闭当前轮（写 `conclusion_text`）→ 开新轮 → 可选链式投递生成任务（同一 `Idempotency-Key` 派生）。

### ⑭ `POST /api/design/tools` — 注册工具

- `201`。`toolCode` 唯一；`realness` **必填**（红线 R1，不接受默认值）。
- `available` **不接受客户端传入**（只能由 `POST /tools/{id}/probe` 回写）—— 否则等于允许伪造能力。

### ⑮ `GET /api/design/stream/{jobNo}` — SSE 增量推送

```
event: progress   data: {"jobNo","status","progress","doneCount","totalCount"}
event: candidate  data: {"candidateId","smiles","inchikey","totalScore"}
event: metric     data: {"candidateId","metricCode","valueNum","normalized"}
event: done       data: {"jobNo","status","result":{}}
```

- **断线重连**：客户端带 `Last-Event-ID`；服务端按事件序号补齐；`?since=<eventId>` 复位。
- 状态存储：Redis `design:progress:{jobNo}`（TTL 24h），**DB 为权威**；Redis 丢失时从 DB 重建只发 `progress`/`done`（降级不失真）。
- 心跳：每 15s 发 `: keep-alive`。

## 5. 权限与归属校验（红线 R4）

**铁律：所有归属校验失败一律返回 `404`，不返回 `403`**（避免资源探测/枚举）。

统一入口：

```java
// 语义：资源不存在 **或** 不属于当前用户 → 抛 DESIGN_*_NOT_FOUND (404)
<T> T assertOwnership(Long ownerId, T entity, String errorCode);
```

| 场景 | 返回 |
|---|---|
| 访问他人项目 | `404 DESIGN_PROJECT_NOT_FOUND` |
| 访问他人候选/任务/报告/实验 | 对应 `*_NOT_FOUND` (404) |
| 已登录但访问管理员接口 | `403 FORBIDDEN`（**唯一使用 403 的场景**） |
| 缺少 JWT 访问 `/api/design/**` | `401 UNAUTHORIZED` |
| 缺少 `X-API-Key` 访问 `/v1/**` | `401 UNAUTHORIZED` |

> **注意 fail-open 历史问题**：既有代码存在 `userId == null` 直接放行的写法（问题总账 `B-12`）。`/api/design/**` **严禁**沿用，`assertOwnership` 对 `ownerId == null` 必须**抛错**（fail-closed）。

## 7. 与 FastAPI 计算层的契约对齐（勘误 R-09 / 裁决 A-1）

### 7.1 现状与目标的差距

| 设计书 §4.6 目标端点 | FastAPI 现值 | 处置 |
|---|---|---|
| `/v1/predict/{dti,ppi,ddi}` | `POST /v1/predict/single`（`algo_type` 区分） | **短期：工具注册指向 `single`**；中期如补别名端点，只改 `design_tool.endpoint`，无需改后端代码 |
| `/v1/predict/batch` | ✅ 已存在 | 复用 |
| `/v1/ddi/drugs` | ✅ 已存在（后端已在用） | 登记为工具 |
| `/v1/evaluate/properties`、`/v1/evaluate/docking`、`/v1/evaluate/admet` | ❌ 未实现 | 待实现；`design_tool.available=0` + `probe_msg` 已如实标注 |
| `/v1/generate`、`/v1/generate/preview`、`/v1/generate/strategies` | ❌ 未实现 | 待实现 |
| `/v1/molecules/*`（scaffold / edit / validate） | ❌ 未实现 | 待实现（RDKit 已随镜像安装） |
| `/v1/pockets/detect`、`/v1/structures/*`、`/v1/targets/resolve` | ❌ 未实现 | 待实现（P2Rank 未部署） |
| `/v1/evaluate/capabilities` | ❌ 未实现 | **优先级最高**：它是 `design_tool.available` 的数据源（红线 R1） |

### 7.2 建议的实施顺序（按"解除阻塞"排序）

1. `GET /v1/evaluate/capabilities` —— 让能力真实性机制**真正运转**（否则 `available` 只能靠种子静态值）；
2. `POST /v1/evaluate/properties`（RDKit 已在镜像里，成本最低、收益最大：一次点亮 8 个指标）；
3. `POST /v1/molecules/edit` + `/validate`（支撑"保存即编译"）；
4. `POST /v1/predict/{dti,ppi,ddi}` 别名（或维持 `single`）；
5. `POST /v1/generate`、`/v1/pockets/detect`、`/v1/structures/*`（依赖新引擎部署）。

详见 [`04-计算层契约与校准协议.md`](./04-计算层契约与校准协议.md)。
