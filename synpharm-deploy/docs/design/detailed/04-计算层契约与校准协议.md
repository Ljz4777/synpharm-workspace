## 2. P0：能力矩阵 `GET /v1/evaluate/capabilities`


### 2.2 设计要点

| 要点 | 说明 |
|---|---|
| **必须复用 `/health/` 的判定逻辑** | 现有的 `get_model_status()`（`services/algorithm_adapters.py`）已区分 `ready` / `not_loaded` / `weights_missing` / `load_failed`（问题总账 `E-01` 已修），直接复用，**不要**另写一套 |
| **不得触发权重加载** | 只读文件存在性；`loaded` 是"是否已加载"的观测值，不是"能否加载"的判定 |
| **`endpoints` 状态取值** | `READY` / `NOT_IMPLEMENTED`（编译期常量，硬编码在能力模块里，与路由表一并维护） |
| 性能 | P95 < 50ms（纯本地检查 + 常量表），可被后端每 10min 拉取 |
| 幂等 | 无副作用；`X-API-Key` 必需 |

> **与 `design_tool.capability_key` 的映射**：`capability_key` 形如 `rdkit`、`models.dti`、`vina`。
> 后端 `ToolRegistryService` 用「先查 `engines[key]`，再查 `models[key.split('.')[1]]`」的规则解析。

## 3. P1：RDKit 计算端点

### 3.1 `POST /v1/evaluate/properties`

一次请求算完一批分子的全部理化/成药性指标，供 `evaluation_result` 逐条落库。

```jsonc
// Request
{
  "molecules": [
    { "ref": "c7788", "smiles": "CC(=O)Oc1ccccc1C(=O)O" },
    { "ref": "c7789", "smiles": "CN1C=NC2=C1C(=O)N(C)C(=O)N2C" }
  ],
  "metrics": ["MOL_WT","MOL_LOGP","TPSA","NUM_H_DONORS","NUM_H_ACCEPTORS","NUM_ROTATABLE",
              "FRACTION_CSP3","QED","LIPINSKI_PASS","SA_SCORE","PAINS_HITS","BRENK_HITS"],
  "includeDiversity": true
}

// Response
{
  "status": "SUCCEEDED",          // SUCCEEDED | PARTIAL | FAILED
  "results": [
    {
      "ref": "c7788",
      "success": true,
      "error": null,
      "metrics": {
        "MOL_WT":       { "value": 180.16,  "grade": null },
        "QED":          { "value": 0.5523,  "grade": null },
        "SA_SCORE":     { "value": 1.58,    "grade": null },
        "PAINS_HITS":   { "value": 0, "detail": [] },
        "LIPINSKI_PASS":{ "value": 4, "detail": { "violations": [] } }
      },
      "canonicalSmiles": "CC(=O)Oc1ccccc1C(=O)O",
      "inchikey": "BSYNRYMUTXBXSQ-UHFFFAOYSA-N",
      "formula": "C9H8O4",
      "diversity": { "maxSimilarity": 0.12 }
    }
  ],
  "engine": { "rdkit": "2024.09.1" }
}
```

**硬约束**：

1. `success=false` 时 `metrics` 可为空 —— 后端据此写 `evaluation_result.success=0`（红线 R2：**不得**返回 0 值填充而非报错）；
2. `PAINS_HITS` / `BRENK_HITS` 的 `detail` 必须给出命中的 SMARTS 列表（前端高亮的依据，也是 `38_` 函数索引的目标）；
3. **不返回** `SELECTIVITY_INDEX` / `DTI_CONFIDENCE` 等需要模型的指标 —— 同批请求一律拒绝，避免"用假数据填充"；
4. 单分子 Sanitize 失败 → 该条 `success=false`，**不中断整批**（返回 `PARTIAL`）。

**实现补充（2026-10-24）**

- 实际支持的指标共 **14 个**：`MOL_WT` / `MOL_LOGP` / `TPSA` / `NUM_H_DONORS` / `NUM_H_ACCEPTORS` / `NUM_ROTATABLE` / `FRACTION_CSP3` / `NUM_RINGS` / `NUM_AROMATIC_RINGS` / `QED` / `LIPINSKI_PASS` / `PAINS_HITS` / `BRENK_HITS` / `COMPLEXITY_PENALTY`
- **`SA_SCORE` 不可得**：依赖 RDKit Contrib 的 `fpscores.pkl.gz`，pip 版不含且当前环境 GitHub 不可达。已列入 `capabilities.metrics.unsupported` 并说明原因；替代品 `COMPLEXITY_PENALTY` 是 SA score 的**复杂度罚项**（环复杂度 + 螺环 + 桥头 + 立体中心 + 大环），命名刻意不同，不冒充原指标
- 响应额外含 `murckoScaffold`（生成 S5 去重的骨架聚类依据）；`includeDiversity=true` 时给出 `diversity.maxSimilarity`（同批最高 Tanimoto）

### 3.2 `POST /v1/molecules/edit` 与 `/validate`

```jsonc
// POST /v1/molecules/edit
{ "parentSmiles": "CC(=O)Oc1ccccc1C(=O)O",
  "type": "ADD_SUBSTITUENT",
  "params": { "atomIdx": 12, "group": "[OH]" } }
// Response
{ "ok": true,
  "childSmiles": "CC(=O)Oc1ccc(O)cc1C(=O)O",
  "childInchikey": "BSYNRYMUTXBXSQ-UHFFFAOYSA-N",
  "changedAtoms": [12],
  "describe": "在 12 位碳上添加羟基",
  "warnings": [] }

// POST /v1/molecules/edit/validate  → 只校验不产出（画布高频调用）
{ "valid": true, "errors": [], "warnings": ["R 基位置可能导致手性中心"] }
```

| 编辑类型 | 是否需 `atomIdx` | 备注 |
|---|---|---|
| `ADD_SUBSTITUENT` / `REMOVE_SUBSTITUENT` / `REPLACE_GROUP` | ✅ | 走 RDKit RWMol |
| `RING_OPEN_CLOSE` / `CHAIN_EXTEND` / `HETERO_SWAP` | ✅ | |
| `STEREO_TUNE` | ✅ | 只改立体标记 |
| `RAW_SMILES` | ❌ | 直接接收完整 SMILES（生物大分子场景） |
| `FRAGMENT_JOIN` | ❌ | 需 `fragments[]` |

**失败语义**：可能产出非法结构 → `400` + `MOLECULE_EDIT_INVALID`；产物与父相同 → `MOLECULE_EDIT_NO_CHANGE`。

## 4. **Q4 校准工件：存储与加载协议**（本设计新增）

> 设计书 §8.3 Q4 原文：「校准工件（`calibrationId`）的**存储与加载**协议未定 → 回灌无法真正生效」。
> 本节给出完整协议。

### 4.1 设计原则

| 原则 | 理由 |
|---|---|
| 回灌**不修改模型权重文件** | 权重是 2.7GB 二进制资产、不可审计、不可回滚 |
| 产出**版本化、内容寻址、不可变**的校准工件 | 可回滚、可审计、可在报告中声明"本轮用的是哪版校准" |
| 校准**显式绑定到预测** | 同一输入 + 同一 `calibrationId` ⇒ 同一输出（可复现） |
| 工件字节存对象存储，**元数据存 DB** | 与 `31_file_asset` 的设计一致 |

### 4.2 工件模型

**Manifest**（小，≤ 256 KB，可直接内联传输）：

```jsonc
{
  "calibrationId": "CAL260103143500E1",
  "schemaVersion": "1.0",
  "algorithm": "DTI",                 // DTI | PPI | DDI | ADMET | DOCKING
  "modelVersion": "kan-modti-1.0.0",  // 必须与被校准模型的版本一致，否则拒绝应用
  "metricCode": "DTI_CONFIDENCE",     // 校准作用于哪个指标
  "mode": "RESIDUAL_FIT",             // RESIDUAL_FIT | ISOTONIC | PLATT | TEMPERATURE
  "targetRole": "MUTANT",             // 可按靶点角色分别校准；null = 不限
  "sampleSize": 21,
  "fittedAt": "2026-01-03T14:35:00+08:00",
  "inputRange": { "min": 0.02, "max": 0.98 },
  "params": {                          // 随 mode 而定；小参数直接内联
    "kind": "LINEAR",
    "a": 0.87, "b": -0.03
  },
  "artifactRef": "file:///app/models/calibrations/CAL260103143500E1/isotonic.json", // 大参数（如 isotonic 断点）走文件
  "artifactSha256": "9f2c…",           // 大参数文件的 sha256（与 file_asset.sha256 一致）
  "stats": {
    "before": { "mae": 3.42, "r2": 0.41, "hitRate": 0.43 },
    "after":  { "mae": 2.71, "r2": 0.63, "hitRate": 0.58 }
  },
  "sourceExperiments": [6612, 6613, 6614],
  "codeVersion": "engine-1.4.2"
}
```

**DB 侧登记**（`file_asset` + `wet_experiment`）：

| 字段 | 内容 |
|---|---|
| `file_asset.sha256` | manifest（或大参数文件）的内容哈希 —— 天然去重 |
| `file_asset.content_type` | `application/vnd.synpharm.calibration+json` |
| `file_asset.object_key` | `calibrations/{sha256[0:2]}/{sha256}` |
| `wet_experiment.calibration_id` | `CAL…`（同一批次内多条实验共享） |
| `wet_experiment.feedback_batch` | `B…`（批次号，与 `calibration_id` 1:1 或 1:N） |

> **`calibrationId` 与 `sha256` 的区别**：`calibrationId` 是**业务标识**（可读、可回滚、可在报告中引用）；`sha256` 是**内容标识**（去重、防篡改）。两者都保留。

### 4.3 存储协议

```
后端（synpharm-backend）                                    引擎（synpharm-fastapi）
  │ 1. 收集 experimentIds → 组装样本（predicted, observed）      │
  │ 2. POST {FASTAPI}/v1/feedback/calibrate ──────────────────► │ 拟合（纯 CPU，无需 GPU）
  │                                                             │ ← 返回 manifest + 大参数（如有）
  │ 3. 事务外：上传 manifest/大参数 → 对象存储                    │
  │ 4. 事务：写 file_asset + UPDATE wet_experiment.feedback_*    │
  │ 5. afterCommit：POST {FASTAPI}/v1/feedback/apply ─────────► │ 装载到内存版本注册表
  │         body: { manifest } 或 { calibrationId, artifactUri } │
```

**传输选择**：

| 情形 | 方式 |
|---|---|
| manifest ≤ 256 KB 且无大参数 | **内联**（`POST /v1/feedback/apply` body 直接带 manifest） |
| 有大参数（isotonic 断点、温度标定曲线） | 后端先上传大参数得 `artifactUri` → `apply` 时带 `{calibrationId, artifactUri, artifactSha256}`，引擎自行下载并**校验 sha256** |
| 引擎与后端共享卷（当前 Docker 部署） | 允许 `file://` URI 直读；生产建议改为内网预签名 URL |

> **安全**：`artifactUri` 只接受**白名单前缀**（`file:///app/models/calibrations/`、`s3://synpharm-calibrations/`、内网预签名域），防止 SSRF。

### 4.4 加载与应用

```
GET  /v1/feedback/calibrations                 → 版本注册表（内存 + 已装载列表，不分页，量级小）
POST /v1/feedback/apply                        → 装载（幂等：同 calibrationId 重复装载直接返回已装载）
POST /v1/feedback/activate                     → 激活某版本（可按 (algorithm, metricCode, targetRole) 维度）
POST /v1/feedback/rollback                     → 回到上一版（等价于 activate 上一个版本）
```

**应用规则**（引擎侧）：

| 规则 | 说明 |
|---|---|
| 按 `(algorithm, metricCode, targetRole)` 索引 | 同一 `targetRole` 的空值 `null` 作为"默认校准"，被具体角色校准覆盖 |
| `modelVersion` 不匹配 → **拒绝激活** | 避免用旧校准校正新模型（返回 `409 CALIBRATION_MODEL_MISMATCH`） |
| 保留最近 **N=20** 个版本 | 超出按 LRU 淘汰（工件本体仍在对象存储，可重新装载） |
| 无校准时的行为 | **不加任何修正**，并在预测响应中回传 `calibrationId: null` |

### 4.5 可复现性闭环（**关键**）

预测响应必须声明所用校准：

```jsonc
// POST /v1/predict/single → 响应增加字段
{
  "status": "success",
  "metrics": { "...": "..." },
  "calibration": { "calibrationId": "CAL260103143500E1", "appliedMetrics": ["DTI_CONFIDENCE"] }
}
```

后端把 `calibrationId` 快照进 `evaluation_result.detail_json.calibrationId`。

于是：

```
同一 (SMILES, target, modelVersion, calibrationId) → 同一输出      ← 可复现
报告引用某数值 → 可追到 (evaluation_run, calibrationId, 引擎版本)  ← 可审计
实测偏差变大 → 回滚到上一版 calibrationId                          ← 可回滚
```

### 4.6 与「实测准确率」的关系

- **校准前**的 `before` 统计来自 `wet_experiment.error_delta` 的历史窗口；
- **校准后**的 `after` 由 `calibrate` 阶段用留出法（hold-out，默认 20%）计算，**样本量 < 10 时拒绝拟合**（返回 `FEEDBACK_NO_SAMPLE`）；
- 报告必须标注使用的是**哪一版校准**及其 `sampleSize`（红线 R2）。

## 5. 服务间安全

| 项 | 规定 |
|---|---|
| 认证 | 除 `/health/` 外**全部**要求 `X-API-Key`（现由 `core/auth.py` 的 `verify_api_key` 提供） |
| **fail-closed** | `API_KEYS` 为空时**必须拒绝**，不得沿用现状"留空则关闭认证"（问题总账 `B-10`：生产默认无认证） |
| 文档端点 | `/docs`、`/redoc`、`/openapi.json` 生产**必须关闭或加鉴权**（现状裸奔） |
| 长度限制 | 请求体与字段长度上限（`drug_smiles` ≤ 2000、序列 ≤ 20000、批量 ≤ `max_batch_size`） |
| 常量时间比较 | `X-API-Key` 比较改 `hmac.compare_digest`（现状 `not in list` 非常量时间，`B-19`） |

> **注意**：`fail-closed` 意味着**开发环境也要配 `FASTAPI_API_KEY`**。当前 `.env` 已设置（随机 32 位 hex），两端一致，可直接启用。

## 6. 错误契约

统一沿用现有 `core/exceptions.py` 的分类，**并补齐 `algo_type`**（问题总账 `E-04`）：

```jsonc
{
  "detail": {
    "errorCode": "SEQUENCE_TOO_SHORT",
    "message": "蛋白序列过短（最少 20 aa），当前 12 aa",
    "algoType": "DTI",
    "field": "target_seq",
    "details": { "minLength": 20, "actualLength": 12 }
  }
}
```

| HTTP | 语义 | 对应后端 errorCode |
|---|---|---|
| 400 | 输入非法（`InvalidInputError`） | `VALIDATION_FAILED` |
| 401 | API Key 缺失/错误 | `UNAUTHORIZED` |
| 404 | 模型未就绪（`ModelNotFoundError`） | → 后端映射为 `DEPENDENCY_UNAVAILABLE` 或 `EVALUATION_METRIC_UNAVAILABLE` |
| 409 | 校准版本冲突 / 模型版本不匹配 | `CALIBRATION_MODEL_MISMATCH` |
| 422 | 药物不在 DDI 训练图内（`OutOfGraphError`，**已有**） | `MODALITY_MISMATCH` 的近亲，后端应提示白名单 |
| 503 | 推理资源不可用 | `DEPENDENCY_UNAVAILABLE` |

**必须保持**：
- 同步 `def` 端点（阻塞推理放线程池）—— 历史 `E-06` 的教训，新增端点**不得**用 `async def` 做阻塞计算；
- 已分类的错误**原样透出**，不得被 `except Exception` 吞成 500（历史 `E-03`）；
- 模型静默兜底**必须显式报错**而非返回占位值（历史 `C-03`）。
