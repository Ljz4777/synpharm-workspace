## 2. 总则（12 条硬性规定）

| # | 规定 |
|---|---|
| G1 | **一个服务只写自己的 schema**。跨服务写一律经 owner 服务的 API 或事件；禁止跨 schema JOIN / 外键（详见 04） |
| G2 | **`errorCode` 字符串是唯一的业务错误标识**，`code` 仅用于聚合统计；前端只允许按 `errorCode` 分支（详见 01） |
| G3 | **所有对外接口经网关**。服务间接口一律 `/internal/**`，网关不暴露、需内部令牌（详见 06） |
| G4 | **计算在 FastAPI**。SpringBoot 侧不得出现化学/模型计算（MCS、描述符、指纹、推理）（红线 R3） |
| G5 | **事务内只做本地写**。MQ 投递一律 `afterCommit`；跨服务 HTTP 不进事务（红线 R5） |
| G6 | **归属校验 fail-closed**。`ownerId == null` 必须拒绝；归属不符一律 404（不 403）（红线 R4） |
| G7 | **能力不可伪造**。`design_tool.available` 只能由探测回写，任何写 API 忽略该字段（红线 R1/R2） |
| G8 | **部分成功必须可见**。`PARTIAL` 结果必须逐项给出原因，并通过信封 `warnings[]` 返回（红线 R1） |
| G9 | **消息必带幂等键**。消费者先校验 job 未终态；唯一键 1062 必须归一化为业务错误码（详见 05） |
| G10 | **密钥不进仓、不进 Nacos**。只走环境变量；缺失时启动失败（fail-fast）（详见 03） |
| G11 | **新增错误码必须登记**。未登记在 01 文档的 `errorCode` 不得合入（详见 01 §7） |
| G12 | **响应不泄露堆栈**。`INTERNAL_ERROR` 只记日志，对外仅给通用文案（详见 01） |

## 3. 红线汇总（沿用并扩展上游设计）

| 红线 | 内容 | 本规范落点 |
|---|---|---|
| **R1** | 能力与真实性的**可见性**：未部署的引擎必须点击前置灰并给原因；部分失败必须逐项说明 | G7、G8、01 §5（`warnings[]`） |
| **R2** | 能力事实单一权威：`design_tool.available` 只由 probe 回写 | G7、06 §5 |
| **R3** | 一切计算在 FastAPI，且 FastAPI 不碰数据库 | G4、06 §4 |
| **R4** | 归属校验 fail-closed，归属不符一律 404 | G6、06 §6 |
| **R5** | 事务边界：事务内只本地写、MQ `afterCommit`、批量独立事务 | G5、05 §1 |
| **R6** | 长任务必须可取消、可观测、可恢复（DB 为权威，Redis 只是投影） | 05 §6、07 §5 |
| **R7** | 幂等：写操作必须可重放不产生副作用 | G9、05 §3 |
| **R8** | 禁止"静默兜底"：看似正常但无意义的算法结果必须记 `success=0` | 05 §6.3、07 §5 |

## 5. 与上游文档的差异（勘误登记）

> 本项目既有 [`00-设计评审与勘误.md`](../design/detailed/00-设计评审与勘误.md) 的勘误惯例，本规范沿用。编号接续为 **C-**（Convention 勘误）。

| # | 差异 | 上游表述 | 本规范规定 | 理由 |
|---|---|---|---|---|
| **C-01** | 成功态 `code` 取值 | [`02-接口层详细设计.md`](../design/detailed/02-接口层详细设计.md) §1.1 用 `"code": 0`；现有实现 [`Result.java`](../../../synpharm-backend/src/main/java/com/synpharm/utils/Result.java) 用 `200` | **统一取 `0`**（对齐设计文档）；成功不再使用 `200` | 设计文档已定稿且规则自洽（`0` 成功 / `4xxxx` / `5xxxx`）；现状只有 2 处前端判定 + 2 处后端工厂方法受影响，切换成本极低。详见 01 §2 |
| **C-02** | 错误码体系数量 | 现状并存三代（`ErrorCode` 整数、`PredictionErrorCode` 字符串、设计域字符串） | **收敛为一套**：`errorCode` 字符串为唯一权威 | 问题总账 D-11 的扩大版 |
| **C-03** | `code` 序号分配 | 设计文档示例为 `40401`（无分配规则） | 引入**块分配表**（服务级号段），`code` 全局唯一可推导 | 避免六服务并行开发时号段冲突。详见 01 §3 |
| **C-04** | 部分成功如何返回 | 设计文档将 `EVALUATION_METRIC_UNAVAILABLE` 标为 `HTTP 200（业务告警）`，但仍放在错误码表 | **移出错误码表**，改为信封新增 `warnings[]` 字段承载 | "HTTP 200 + errorCode" 语义矛盾；`warnings` 同时满足红线 R1 的可见性要求。详见 01 §5 |
| **C-05** | 工具类接口的路径与服务归属 | 设计文档 `/api/design/tools/**` 随设计域 | 数据归 `synpharm-platform`，**路径前缀保持不变**，由网关按路径路由 | 路径前缀表达**前端功能域**，服务归属由路由表决定。详见 02 §2 |
| **C-06** | `fk_er_tool` 外键 | `36_` 延迟补建 `evaluation_result → design_tool` | **永久不建** | `evaluation_result` 对 `realness`/`source_tool_id` 是**快照**语义，本就不需要引用完整性 |
| **C-07** | 任务状态字典 | 现状 `batch_task.status` 用 `SUCCESS`/`FAIL`（TINYINT 0~3）；设计域用 `SUCCEEDED`/`FAILED` | **统一为设计域字典**：`PENDING`/`RUNNING`/`SUCCEEDED`/`PARTIAL`/`FAILED`/`CANCELLED`；`batch_task` 按状态机图迁移 | 上游[设计域统一任务状态机](../uml/设计域.md#63-统一任务-design_job) 已明确"把既有 `SUCCESS` 统一更名为 `SUCCEEDED`，全域共用一个字典"；本规范此前误用 `SUCCESS`，已更正。详见[批量任务状态机](../uml/业务流程.md#5-批量任务状态机) |
