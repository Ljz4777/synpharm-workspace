## 1. Maven 多模块结构

```
synpharm-parent/                          # 只做依赖管理 + 版本统一
├── pom.xml                               # packaging=pom；dependencyManagement 收敛全部版本
├── synpharm-common/                      # 无业务：信封、错误码、异常、过滤器、MyBatis 配置、工具
├── synpharm-api/                         # 服务间契约：Feign 接口 + 共享 DTO（无实现）
├── synpharm-job-core/                    # 任务框架：job 生命周期/幂等键/进度/SSE 支持（无进程）
├── synpharm-gateway/
├── synpharm-auth/
├── synpharm-predict/
├── synpharm-design/
├── synpharm-asset/
└── synpharm-platform/
```

| 规则 | 说明 |
|---|---|
| 版本统一 | 所有版本号在 `synpharm-parent` 的 `dependencyManagement` 声明；子模块**不写** `<version>`（继承） |
| 版本对齐 | Spring Boot `3.3.5` → Spring Cloud `2023.0.x` → Spring Cloud Alibaba `2023.0.3.3`（**落地前再核对一次矩阵**） |
| 依赖方向 | `服务 → synpharm-api / synpharm-common / synpharm-job-core`；三者**互不依赖**，且**不依赖**任何服务 |
| 禁止 | 服务之间互相依赖（只允许依赖 `synpharm-api`）；`common` 里放业务代码 |
| 构建产物 | 每个服务一个可执行 fat jar；`common`/`api`/`job-core` 不打可执行 jar |
| 统一插件 | `maven-compiler-plugin`（Java 17 + `-parameters`）、`spring-boot-maven-plugin`、`jacoco`、`maven-enforcer-plugin`（依赖收敛） |

## 2. 包结构（每服务统一）

```
com.synpharm.{service}
├── api/                     # ① 接口层：@RestController + dto/
├── application/             # ② 应用层：@Service 用例编排 + @Transactional
├── domain/                  # ③ 领域层：纯逻辑（无 Spring 注解、无 IO）
│   ├── model/               #    实体 / 值对象
│   ├── repo/                #    仓储接口
│   └── {rules}/             #    约束求值 / 评分 / 血缘 / 能力规则 …
├── infrastructure/          # ④ 基础设施
│   ├── persistence/         #    Mapper + XML
│   ├── client/              #    Feign / WebClient
│   ├── mq/                  #    Producer / Consumer / Config
│   ├── cache/               #    Redis 封装
│   └── storage/             #    对象存储
├── support/                 # 横切：错误码、Assembler、Guard、Idempotency
└── {Service}Application.java
```

**计算层例外**：`predict` 保留既有 `pipeline/`（解析器/执行器/格式化器）与 `client/`，不强行套四层 —— 它已是策略+工厂结构（见 [`../architecture/架构设计文档.md`](../architecture/架构设计文档.md) §5），按"服务于功能清晰的既有结构"原则沿用。

### 2.1 依赖方向铁律

```
api → application → domain ← infrastructure
```

| 层 | 做 | **不做** |
|---|---|---|
| `api` | `@Valid` 参数校验、归属校验、DTO 装配、状态码（201/202） | 业务判断、`@Transactional`、直接调 Mapper |
| `application` | 用例编排、事务边界、`afterCommit` 投递、跨聚合视图组装 | 写 SQL、拼 JSON、调 HTTP（走 infrastructure 接口） |
| `domain` | 规则求值、评分、血缘、能力规则 | **任何 IO**（DB/HTTP/Redis/文件） |
| `infrastructure` | Mapper/XML、Feign、MQ、Redis、对象存储 | 业务规则 |

> `domain` **不得**依赖 `infrastructure`（仓储走接口）；`api` **不得**直接调 `infrastructure`。

## 4. 编码约定

### 4.1 通用

| 项 | 规定 |
|---|---|
| Java 版本 | 17（`records` 用于 DTO/值对象；`sealed` 用于状态机节点可选） |
| Lombok | `@Data` 仅用于 DTO/实体；**禁止**在 `domain` 模型上滥用 `@Data`（可变性失控），优先 `@Getter` + 构造器 |
| 空值 | 返回值禁止返回 `null` 集合（返回空集合）；可选值用 `Optional` **仅**作返回类型 |
| 异常 | 业务异常用 `BusinessException(ErrorCode)`；**禁止** `catch (Exception e) {}` 空捕获 |
| 校验 | `jakarta.validation` 分组（`Create`/`Update`）；参数校验在 `api` 层 |
| 时间 | 统一 `java.time`（`LocalDateTime`/`Instant`）；**禁止** `java.util.Date` |
| 金额/比例 | `BigDecimal`；**禁止** `double` 参与金额运算 |
| 日志 | 见 §5；**禁止** `System.out.println` |
| 魔法值 | 抽为常量或枚举 |
| 注释 | 只注释**需要澄清**的地方（复杂规则、非直觉取舍、外部系统怪癖）；**禁止**逐行翻译式注释 |
| 事务 | 见 [`05-事务幂等与消息规范.md`](03-事务消息与安全规范.md) §1 |

### 4.2 禁止事项（CI 可静态检查）

| # | 禁止 | 检查手段 |
|---|---|---|
| 1 | `SELECT *` | 代码审查 + SQL 解析 |
| 2 | 字符串拼接 SQL / `ORDER BY ${}` | 代码审查 |
| 3 | 在 `domain` 包引入 JDBC/HTTP/Redis | ArchUnit |
| 4 | 在 `api` 层出现 `@Transactional` | ArchUnit |
| 5 | 服务之间直接依赖（非 `synpharm-api`） | `maven-enforcer` |
| 6 | 硬编码密钥/IP/绝对路径 | 正则扫描 + `gitleaks` |
| 7 | 空 `catch` 块 | ArchUnit / SpotBugs |
| 8 | `System.out` / `printStackTrace` | 正则扫描 |
| 9 | 事务内调 `FastApiClient`/Feign | 代码审查（关键红线） |
| 10 | 前端做化学计算 | 代码审查（红线 R3） |

## 5. 日志与可观测性规范

### 5.1 日志格式

**必须**输出结构化 JSON 到 stdout（容器日志采集）：

```jsonc
{
  "ts":        "2026-10-14T10:00:01.123+08:00",
  "level":     "INFO",
  "service":   "synpharm-design",
  "traceId":   "b7c1e2a4f8...",
  "requestId": "5f2b...",
  "userId":    1024,
  "logger":    "com.synpharm.design.application.GenerationAppService",
  "msg":       "generation job submitted",
  "jobId":     8891,
  "jobNo":     "J260101120001A7F3",
  "durationMs": 42
}
```

| 字段 | 说明 |
|---|---|
| `traceId` | 来自 `X-Trace-Id`（网关生成），写入 MDC，跨服务 + MQ 透传 |
| `requestId` | 单次请求 ID |
| `userId` | 来自 `X-User-Id`（写入 MDC） |
| 业务字段 | 关键业务标识（`jobId`/`projectId`/`runId`）**必须**作为结构化字段，便于检索 |
| 脱敏 | 见 [`06-服务间调用与安全规范.md`](03-事务消息与安全规范.md) §7.2 |

### 5.2 级别使用

| 级别 | 用途 | 示例 |
|---|---|---|
| `ERROR` | 需要人介入的故障 | 下游不可用、消息投递失败、DLQ 有消息 |
| `WARN` | 可自愈但需关注 | 重试成功、降级触发、越权尝试、疑似静默兜底 |
| `INFO` | 关键状态流转 | job 状态变更、审批决策、登录成功 |
| `DEBUG` | 排查细节（**生产关闭**） | 入参出参、SQL |

| # | 规则 |
|---|---|
| 1 | **生产禁止** `DEBUG` 与 MyBatis `StdOutImpl`（问题总账 B-13） |
| 2 | 日志**不得**成为唯一真相（关键事实必须落库） |
| 3 | 循环内**禁止**逐条打 `INFO`（改批量汇总） |
| 4 | 异常日志**必须**带堆栈（`log.error(msg, e)`），**但**对外响应不带堆栈 |
| 5 | 慢调用（> 1s）**必须**打 `WARN` + `durationMs` |

### 5.3 指标（Micrometer）

| 指标 | 类型 | 标签 |
|---|---|---|
| `http.server.requests` | Timer | `service`, `uri`, `method`, `status` |
| `design.job.duration` | Timer | `jobType`, `status` |
| `design.job.count` | Counter | `jobType`, `status`（含 `PARTIAL`） |
| `fastapi.call.duration` | Timer | `endpoint`, `algoType`, `status` |
| `mq.consume.duration` | Timer | `queue`, `success` |
| `tool.probe.result` | Gauge | `toolCode`, `available` |
| `cache.hit.ratio` | Gauge | `cacheName` |
| `db.pool.usage` | Gauge | `service` |

### 5.4 健康检查与探针

| 端点 | 用途 | 内容 |
|---|---|---|
| `/actuator/health/liveness` | K8s liveness | 进程存活（不含下游） |
| `/actuator/health/readiness` | K8s readiness | DB + Redis + MQ 可达 |
| `/actuator/health` | 综合（**仅内网**） | 全部组件；**生产只暴露 `health`** |
| `/actuator/info` | 版本信息 | `git.commit`、`build.time` |

> **必须修复问题总账 E-01**：FastAPI `/health` 恒返回 healthy —— 必须**真实**探测模型加载与依赖。

### 5.5 告警基线

| 条件 | 级别 |
|---|---|
| DLQ 消息数 > 0 | P1 |
| `http.server.requests` 5xx 比例 > 1%（5min） | P1 |
| `design.job.count{status=FAILED}` 增长率异常 | P1 |
| `tool.probe.result{available=0}` 覆盖核心工具 | P2 |
| `PARTIAL` 比例 > 20% | P2 |
| DB 连接池使用率 > 85% | P2 |
| 慢调用 P95 > 阈值（见 §5.6） | P2 |

### 5.6 性能预算

| 链路 | 目标 |
|---|---|
| 只读接口 P95 | < 300ms |
| 排行榜翻页 P95 | < 300ms（键集分页） |
| 编辑（保存即编译） P95 | < **1.5s**（`/v1/molecules/edit` ≤ 400ms + `/v1/evaluate/properties` ≤ 600ms） |
| 单条预测 P95 | < 3s |
| 能力矩阵查询 P95 | < 100ms（走缓存） |
| 网关额外开销 P95 | < 20ms |

## 6. 测试规范

### 6.1 分层

| 层 | 手段 | 覆盖目标 | 是否进 CI |
|---|---|---|---|
| **数据层** | DDL 实测（空库 + 幂等两轮） | 建表、唯一键、生成列不变式 | ✅ |
| **领域层** | 纯单测（无 Spring） | 约束求值、得分归一化与权重重分配、血缘成环、静默兜底识别、状态机迁移 | ✅ |
| **应用层** | `@SpringBootTest` + **Testcontainers**（MySQL/Redis/RabbitMQ） | 事务边界、幂等（重复提交返回同一 job）、1062 归一化、归属 404 | ✅ |
| **接口层** | `MockMvc` 契约测试 | 信封结构、`errorCode`、分页、`warnings[]` | ✅ |
| **服务间** | Feign 契约测试（`openapi.yaml` / 共享 DTO 编译期校验） | 跨服务契约不漂移 | ✅ |
| **端到端** | 冒烟脚本 | 立项→生成→编辑→评估→报告→审批→湿实验→回灌→下一轮 | ✅（**必须**，教训 I-09） |

### 6.2 强制规则

| # | 规则 |
|---|---|
| 1 | **批量链路冒烟测试必须进 CI**（历史教训 I-09：CHANGELOG 声称已修但实际回归） |
| 2 | 计算层（FastAPI）**必须有 pytest** —— 现状零测试（问题总账 H-05） |
| 3 | 每条**红线**至少一个测试：R1（`warnings[]` 出现）、R2（能力回写）、R3（domain 无 IO）、R4（归属 404）、R5（afterCommit）、R7（重复提交幂等）、R8（静默兜底 `success=0`） |
| 4 | 测试**不得**依赖真实外部网络（UniProt/RCSB/PubMed 用 `MockWebServer` / WireMock） |
| 5 | 集成测试用 Testcontainers，**不得**连本地已安装的 MySQL/Redis |
| 6 | 禁止 `@Disabled` 长期留存（要么修要么删，需注明 issue 号） |

### 6.3 覆盖率门槛

| 层 | 线覆盖 | 分支覆盖 |
|---|---|---|
| `domain` | **≥ 80%** | ≥ 70% |
| `application` | ≥ 60% | ≥ 50% |
| `api` | ≥ 50% | — |
| `infrastructure` | 不计入（由集成测试覆盖） | — |

> 覆盖率是**门槛不是目标**：红线相关逻辑**必须**有测试，覆盖率再高也不能替代。

## 7. 部署与运维规范

### 7.1 端口分配

| 组件 | 宿主端口 | 容器内 | 对外 |
|---|---|---|---|
| gateway | **8080** | 8080 | ✅ |
| frontend | 80 | 8080 | ✅ |
| fastapi | 18050 | 8000 | 仅内网（生产建议不映射） |
| mysql | 13307（本机端口冲突，见 `.env`） | 3306 | 仅内网（生产不映射） |
| redis | 6380 | 6379 | 仅内网 |
| rabbitmq | 15672（管理台） | 5672 / 15672 | 管理台仅内网 |
| auth / predict / design / asset / platform | **不映射** | 8081 / 8082 / 8083 / 8084 / 8085 | ❌ |

> **frontend 与 nginx 零改动**：网关占 8080，与既有 `BACKEND_PORT=8080` 及前端 dev 回退地址一致（见 [`../architecture/SpringCloud微服务重构方案.md`](../architecture/SpringCloud微服务重构方案.md) §10.1）。

### 7.2 Dockerfile 规范

| 项 | 规定 |
|---|---|
| 多阶段构建 | `maven:3.9-eclipse-temurin-17`（构建）→ `eclipse-temurin:17-jre-jammy`（运行） |
| 非 root | **必须**创建非 root 用户运行 |
| 时区 | `TZ=Asia/Shanghai` + `tzdata` |
| 健康检查 | `HEALTHCHECK` 指向 `/actuator/health/readiness` |
| JVM 参数 | 容器感知：`-XX:MaxRAMPercentage=75 -XX:+UseContainerSupport` |
| 层缓存 | 先 `COPY pom.xml` + `dependency:go-offline`，再 `COPY src` |
| 镜像标签 | **禁止** `latest`；用版本号或 commit SHA |
| 尺寸 | 单服务镜像 < 400MB（JRE + fat jar） |

### 7.3 资源与伸缩

| 服务 | CPU 请求/限制 | 内存请求/限制 | 副本（初始） | 伸缩依据 |
|---|---|---|---|---|
| gateway | 0.25 / 1 | 512Mi / 1Gi | 2 | QPS |
| auth | 0.25 / 1 | 512Mi / 1Gi | 2 | QPS |
| predict | 0.5 / 2 | 1Gi / 2Gi | 2 | 队列深度 |
| design | 0.5 / 2 | 1Gi / 2Gi | 2 | 队列深度 + SSE 连接数 |
| asset | 0.25 / 1 | 512Mi / 1Gi | 2 | 带宽 |
| platform | 0.25 / 1 | 512Mi / 1Gi | 1~2 | 探测周期 |
| fastapi | 按 GPU 规划 | — | 1~N | GPU 利用率（**独立伸缩**） |

### 7.4 发布与回滚

| 项 | 规定 |
|---|---|
| 策略 | 滚动发布（`maxSurge=1, maxUnavailable=0`）；`readiness` 通过后才接流量 |
| 优雅停机 | `server.shutdown: graceful` + `preStop` 等待 **30s**（排空 SSE 与在途请求） |
| DB 迁移 | **先**执行向后兼容的迁移（只增列/表/索引），**再**发新版本；删列/改类型需**两阶段**（先停用代码，下个版本再删） |
| 兼容窗口 | 一个发布周期内新旧版本必须共存（接口只增字段、事件只增字段） |
| 回滚 | 镜像回滚**必须**可用（因此禁止不可逆的 DB 变更）；配置回滚走 Nacos 历史版本 |
| 灰度 | 网关按 header/用户比例分流（可选） |
| 发布窗口 | 生产变更需变更单；`JWT_SECRET` 轮换需公告（强制重登） |

### 7.5 环境矩阵

| 环境 | 编排 | Profile | 数据 | 密钥 |
|---|---|---|---|---|
| 本地 | `docker-compose.dev.yml` | `dev` | 本地 MySQL | `.env`（不入仓，**已 gitignore**） |
| 测试 | `docker-compose.yml` | `docker` | 独立实例 | CI Secret |
| 生产 | K8s / Compose | `prod` | 独立实例 + 备份 | K8s Secret / Vault |
