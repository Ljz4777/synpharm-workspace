#### 2.2 步骤1：安装基础依赖

##### Windows环境

**JDK 21安装**：
```powershell
## 下载JDK 21
## https://adoptium.net/temurin/releases/?version=21

## 验证安装
java -version
## 输出: openjdk version "21.0.x"

## 设置环境变量（PowerShell）
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.x.x-hotspot"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
```

**Maven安装**：
```powershell
## 下载Maven
## https://maven.apache.org/download.cgi

## 验证安装
mvn -version
## 输出: Apache Maven 3.9.x
```

**Python 3.10+安装**：
```powershell
## 下载Python
## https://www.python.org/downloads/

## 验证安装
python --version
## 输出: Python 3.10.x 或更高
```

**MySQL安装**：
```powershell
## 方式1：下载MySQL Installer
## https://dev.mysql.com/downloads/installer/

## 方式2：使用Docker（推荐）
docker run -d --name mysql-synpharm `
  -p 3306:3306 `
  -e MYSQL_ROOT_PASSWORD=root123 `
  -e MYSQL_DATABASE=synpharm `
  -e MYSQL_USER=synpharm `
  -e MYSQL_PASSWORD=synpharm_pass `
  mysql:8.0

## 验证
docker exec -it mysql-synpharm mysql -u synpharm -psynpharm_pass -e "SELECT 1"
```

**Redis安装**：
```powershell
## 方式1：使用Memurai（Windows版Redis）
## https://www.memurai.com/

## 方式2：使用Docker（推荐）
docker run -d --name redis-synpharm `
  -p 6379:6379 `
  redis:7-alpine

## 验证
docker exec -it redis-synpharm redis-cli ping
## 输出: PONG
```

**RabbitMQ安装**（批量预测消息队列，v3.1.0 起必需）：
```powershell
## Docker（推荐）
docker run -d --name rabbitmq-synpharm `
  -p 15672:15672 `
  -e RABBITMQ_DEFAULT_USER=synpharm `
  -e RABBITMQ_DEFAULT_PASS=synpharm_pass `
  rabbitmq:3.13-management-alpine

## 验证（管理台：http://localhost:15672，账号 synpharm / synpharm_pass）
docker exec -it rabbitmq-synpharm rabbitmq-diagnostics ping
## 输出: Ping succeeded
```

#### 2.8 常见启动问题排查

| 问题 | 原因 | 解决方案 |
|:---|:---|:---|
| 端口8080被占用 | 其他服务占用 | `netstat -ano \| findstr :8080` 找到PID后结束进程 |
| 端口8000被占用 | 其他服务占用 | `netstat -ano \| findstr :8000` 找到PID后结束进程 |
| MySQL连接失败 | 服务未启动或配置错误 | 检查MySQL是否启动，确认用户名密码正确 |
| Redis连接失败 | 服务未启动 | 检查Redis是否启动，确认端口6379 |
| FastAPI依赖安装失败 | 网络问题 | 使用国内镜像源：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| Maven编译失败 | 依赖下载慢 | 配置Maven国内镜像（阿里云） |
| 前端启动失败 | node_modules损坏 | 删除node_modules重新安装：`rm -rf node_modules && npm install` |

#### 3.3 一键启动

```bash
## 进入编排目录（注意是 deploy，不是 docker）
cd d:\SynPharm\deploy

## Windows：直接双击，或在终端执行
scripts\start.bat

## Linux / macOS / WSL
./scripts/start.sh
```

`start.bat` 会自动定位 `docker` 命令、按需拉起 Docker Desktop、创建并修复 `.env`，
然后校验配置并启动全部服务。首次需 10~30 分钟构建，之后秒级启动。

脚本会等到全部服务 healthy 才返回，等价于：

```bash
docker compose up -d --wait --wait-timeout 600
docker compose ps          # 预期全部 healthy：
##   synpharm-mysql      healthy
##   synpharm-redis      healthy
##   synpharm-rabbitmq   healthy
##   synpharm-fastapi    healthy
##   synpharm-backend    healthy
##   synpharm-frontend   healthy
```

需要停止时：

```bash
scripts\stop.bat           # 或 ./scripts/stop.sh
```

> 改了源码要重建镜像：`scripts\start.bat rebuild`
> （日常启动会跳过构建，避免重复下载 185 MB 的 torch）

#### 3.4 服务端口映射

> 端口均可通过 `deploy/.env` 的 `*_PORT` 变量修改。下表为**默认值**与**本项目当前 `.env` 实际值**（实际以 `.env` 为准）。

| 服务 | 容器端口 | 主机端口(默认) | 本项目 `.env` 实际值 | 说明 |
|:---|:---|:---|:---|:---|
| Spring Boot | 8080 | 8080 | **7000** | 业务API |
| FastAPI | 8000 | 8000 | **18050** | 算法引擎 |
| MySQL | 3306 | 3306 | **13307** | 数据库（3307-3406 属 Windows 保留端口段，不可用） |
| Redis | 6379 | 6379 | **6380** | 缓存 |
| RabbitMQ | 5672 / 15672 | 不映射 / 15672(仅内网) | **15672**(仅内网) | AMQP 仅内网访问；管理台仅内网暴露 |
| 前端 Nginx | 8080(容器) | 80 | **80** | 静态站点 + `/api` 反代 |

#### 3.10 常见Docker问题排查

| 问题 | 原因 | 解决方案 |
|:---|:---|:---|
| Docker未运行 | Docker Desktop未启动 | 启动Docker Desktop |
| 端口被占用 | 其他服务使用了端口 | 停止占用服务或修改docker-compose端口映射 |
| 数据库连接失败 | MySQL未就绪 | 等待健康检查通过：`docker-compose ps` |
| 构建失败 | 网络问题或依赖缺失 | 检查网络，确保Docker Hub可访问 |
| 服务启动慢 | 首次构建需要下载镜像 | 耐心等待，国内用户可配置镜像加速 |
| 日志显示连接拒绝 | 服务启动顺序问题 | 使用`depends_on`的`service_healthy`条件 |

## 第二部分 · 容器化与 Docker 环境


> 版本：v2.0（企业级容器化重构）
> 更新日期：2026-07-31
> 适用范围：开发 / 测试 / 组员协作环境

### 1. 背景与目标

本项目早期将 Docker 相关文件散落在多个位置（根目录 `docker/`、各服务目录、多个硬编码配置），导致：

- 组员 clone 后无法一键启动；
- 前端未容器化（compose 中缺失 frontend 服务）；
- 密钥/密码硬编码在配置与编排文件中，存在安全隐患；
- FastAPI 存在致命导入错误，容器即使构建成功也无法启动；
- 健康检查配置无效（使用了不存在的 `curl` 与错误的探测端点）。

本重构按**企业级开发范式**对全部 Docker/环境文件进行了统一治理，目标：

| 目标 | 落地方式 |
|---|---|
| 干净隔离 | 每个服务独立容器，互不污染宿主机 |
| 组员可复现 | 一个命令一键启动，环境变量模板化 |
| 可配置 | 全部敏感配置收口到 `deploy/.env` |
| 可运维 | Actuator/curl 健康检查、日志、数据卷 |
| 安全 | 非 root 运行、多阶段构建、密钥不入库 |

**设计决策说明：**

| 决策 | 理由 |
|---|---|
| Dockerfile 跟随各服务源码 | 构建上下文干净、Dockerfile 与代码同版本同分支（业界主流） |
| 编排/配置/脚本集中在 `synpharm-deploy/` | "运行描述"与"代码"分离，组员只需关注一个入口 |
| 前端使用 nginx-unprivileged | 非 root 运行 Nginx，符合最小权限原则 |
| 模型文件不进镜像 | 模型体积大且更新频繁，统一卷挂载便于替换 |
| 微服务工程独立成 `synpharm-cloud/` | 绞杀式迁移：单体 `synpharm-backend` 原地不动（无 git、128 个类不可搬），始终是可用的对照基线；被抽空的模块逐个从单体消失 |
| 网关 Dockerfile 放在多模块根目录 | 网关依赖 `synpharm-common`，构建上下文必须是整个 reactor 才能 `mvn package` |

```powershell
  mysql redis rabbitmq nacos mvn-setup gateway auth predict design asset platform
```

> ⚠️ **单体 `synpharm-backend` 已于 2026-10-16 退役**，不再在服务列表里。
> 退役依据与六项清收动作见[方案 §11.5](../architecture/SpringCloud微服务重构方案.md)。
> 源码目录 `synpharm-backend/` 仍保留在工作区（回滚用），**SQL 脚本已搬到 `synpharm-deploy/sql/`**。
> 单体退役后，未被任何路由匹配的 `/api/**` 由网关返回 **404 + 统一信封**
> （`RESOURCE_NOT_FOUND`），下游服务不可达则返回 **503 + `DEPENDENCY_UNAVAILABLE`**。

> **`mvn-setup` 跑的是 `mvn -B -q -DskipTests clean install`**（一次性服务，`restart: "no"`）：
> 先把 `synpharm-common` 装进本地仓库，各服务再各自 `mvn -B clean spring-boot:run`。
> **改了 `synpharm-common` 必须重跑**：
> `docker compose --env-file .env -f synpharm-deploy/docker-compose.dev.yml up -d --force-recreate mvn-setup`
>
> ⚠️ **两条 `clean` 都不能省**（问题总账 H-21 / H-22）。宿主 VS Code 的 Java 语言服务器会
> 自动重编译并**直接覆盖共享的 `target/classes`**，其产物曾多次出现非法的字节码
> （容器内报 `ClassFormatError: Invalid method Code length 0`）。而 maven 按时间戳判断会认为
> "已是最新"从而**跳过编译**：服务端表现为**在重启循环里永远起不来**，`mvn-setup` 端则表现为
> **把坏的 class 直接打进 m2 的 jar**，导致全部服务一起挂。`clean` 强制 javac 全量重编译，
> 是这条链路的自愈手段；代价是每次启动多一次全量编译（design 114 个类约 +15s）。
> 另外已在 `.vscode/settings.json` 关掉 `java.autobuild.enabled` 以切断污染源
> —— 因此**编译期错误提示请以容器内 `mvn clean test` 为准**，不要依赖编辑器。
>
> 排查这类问题的工具是 `JarClassCheck`（把 jar 挂 `URLClassLoader`、逐个 `Class.forName` + 反射取方法）。
> **不要用 `javap` 验收**：`javap` 只按属性表读、**不校验 `Code_length`**，坏类在它眼里完全正常。

| 入口 | 地址 |
|---|---|
| 网关（唯一外部入口） | http://localhost:8080 |
| Nacos 控制台 | http://localhost:18848/nacos （开发环境 `nacos` / `nacos`） |

> 原「后端直连（绕过网关排查）http://localhost:18081」入口随单体退役（2026-10-16）一并消失。


**无需手动创建 `.env`。** `start.bat` 会自动：

- 创建并修复 `.env`：**只补空值和 `change-me*` 占位值，不会覆盖你自己设过的密码**
- 端口预检 → 校验配置 → 启动（已有容器时跳过端口检查）

| 场景 | 耗时 |
|---|---|

| 之后（镜像已存在） | 十几秒：跳过构建，只 `up -d` |

> 覆盖后密码对不上，之后所有启动都会失败。详见 `deploy/环境配置说明.md` 的
> “启动失败的三大真实原因”。

### 7. 镜像构建（企业级要点）

#### 7.1 多阶段构建

| 服务 | 构建阶段 | 运行阶段 |
|---|---|---|
| backend | `maven:3.9.6-eclipse-temurin-17` → 打包 jar | `eclipse-temurin:17-jre` |
| fastapi | `python:3.11-slim` → pip `--prefix=/install` | `python:3.11-slim` 拷贝依赖产物 |
| frontend | `node:20-alpine` → `npm ci && npm run build` | `nginxinc/nginx-unprivileged:1.27-alpine` |
| gateway / auth / predict / design / asset / platform | `synpharm-cloud/Dockerfile`（**一份覆盖全部服务**） | `eclipse-temurin:17-jre-jammy` |

**微服务镜像用 `MODULE` 参数选择服务**（构建上下文是多模块根目录，不是模块目录）：

```powershell
cd d:\synpharm-workspace
docker build -t synpharm/gateway:1.0.0 synpharm-cloud
docker build -t synpharm/auth:1.0.0     --build-arg MODULE=synpharm-auth     --build-arg SERVER_PORT=8081 synpharm-cloud
docker build -t synpharm/predict:1.0.0  --build-arg MODULE=synpharm-predict  --build-arg SERVER_PORT=8082 synpharm-cloud
docker build -t synpharm/design:1.0.0   --build-arg MODULE=synpharm-design   --build-arg SERVER_PORT=8083 synpharm-cloud
docker build -t synpharm/asset:1.0.0    --build-arg MODULE=synpharm-asset    --build-arg SERVER_PORT=8084 synpharm-cloud
docker build -t synpharm/platform:1.0.0 --build-arg MODULE=synpharm-platform --build-arg SERVER_PORT=8085 synpharm-cloud
```

> ⚠ **新增模块时必须同步 Dockerfile 的 COPY 列表**。Maven 读父 POM 的 `<modules>` 时会逐个
> 校验目录存在，构建上下文里缺一个就报 `Child module ... does not exist` 并整体失败 ——
> 阶段 1 加了 `synpharm-auth` 之后，镜像构建就一直处于这个坏状态（阶段 2B 才发现并修掉）；
> 阶段 3/4/5 新增 `asset` / `platform` / `predict` 后**同一个坑又踩了一次**（三份 pom 都没进
> COPY 列表，阶段 4 才发现并修掉）。dev 编排走源码挂载，因此**这类缺陷只在 prod 镜像制下暴露**。
>
> ⚠ 运行阶段基础镜像**钉 `-jammy`**，不要用浮动的 `:17-jre`：浮动标签会飘到最新的 Ubuntu
> 发行版，而 `archive.ubuntu.com` 在国内网络下经常超时（实测 `resolute/universe` 索引直接
> `Ign` 掉，`apt-get` 以 100 退出，表现为莫名其妙的构建失败）。

运行镜像中**不包含**编译工具链（Maven/npm/pip 缓存），显著减小体积并减少攻击面。

#### 7.2 非 root 运行

三个应用镜像均创建 `appuser`（uid 10001）并以 `USER appuser` 运行：

```dockerfile
RUN useradd --system --uid 10001 --create-home appuser \
    && chown -R appuser:appuser /app
USER appuser
```

#### 7.3 .dockerignore

各服务目录均配置 `.dockerignore`，排除 `target/`、`node_modules/`、`__pycache__/`、`venv/`、日志、`.env` 等，防止构建上下文臃肿与敏感信息泄漏。

### 10. 常见问题排查

| 症状 | 排查步骤 |
|---|---|
| 后端一直 unhealthy | `docker compose logs backend`；检查 DB 密码/JWT_SECRET 是否正确 |
| FastAPI 一直 unhealthy | `docker compose logs fastapi`；首次构建安装 torch 较慢，耐心等待 |
| 端口被占用 | 修改 `.env` 对应端口后重启 |
| 前端打不开 | 确认 `FRONTEND_PORT`、后端是否 healthy；`docker compose ps` |
| MySQL 初始化脚本未执行 | 删除 `mysql_data` 卷后重启：`docker compose down -v && scripts/start` |
| 构建报 `failed to fetch anonymous token` / `auth.docker.io:443` 超时 | 见下方「受限网络下拉取镜像」 |
| 容器启动报 `bind: ... forbidden by its access permissions` | 见下方「Windows 保留端口段」 |

#### 10.1 受限网络下拉取镜像失败

**症状**：`docker compose up --build` 在 `FROM` 阶段就失败，报
`failed to fetch anonymous token` 或 `dial tcp ...:443: connectex: ... did not properly respond`。
此时应用代码根本没被执行，是基础镜像没拉下来。

**原因**：Docker Desktop **不会**自动读取 Windows 的系统代理设置。
当本机无法直连 Docker Hub 时，引擎只能裸连，必然超时。

**三种解法，任选其一：**

1. **配置镜像加速源（推荐，不依赖代理）**

   编辑 `%USERPROFILE%\.docker\daemon.json`（Linux/macOS 为 `/etc/docker/daemon.json`）：

   ```json
   {
     "registry-mirrors": [
       "https://docker.m.daocloud.io",
       "https://docker.1ms.run",
       "https://docker.1panel.live"
     ]
   }
   ```

   然后重启引擎：Windows 用 `docker desktop restart`，Linux 用 `sudo systemctl restart docker`。

   验证：

   ```bash
   docker info --format "{{json .RegistryConfig}}"   # 应能看到 Mirrors 列表
   docker pull alpine:latest                          # 用一个未缓存的镜像验证
   ```

2. **给 Docker 配置代理**（需自备可用代理）
   Docker Desktop → Settings → Resources → Proxies 填代理地址。
   ⚠️ 引擎运行在 WSL2 虚拟机内，代理地址必须写 `http://host.docker.internal:<端口>`，
   **不能写 `127.0.0.1`**（在 VM 里它指向 VM 自己）。

3. **换到可直连 Docker Hub 的网络**后重试。

> Python 依赖同样需要国内源：`synpharm-fastapi/Dockerfile` 默认使用阿里云 PyPI 与
> PyTorch CPU wheel 镜像，如需改回官方源，可用 `--build-arg` 覆盖
> `PIP_INDEX_URL` / `PYTORCH_WHEELS_URL`。

#### 10.2 Windows 保留端口段导致容器无法启动

**症状**：镜像构建成功，但容器启动时报

```text
Error response from daemon: ports are not available: exposing port TCP 0.0.0.0:3307 -> ...:
listen tcp 0.0.0.0:3307: bind: An attempt was made to access a socket in a way forbidden by its access permissions.
```

**原因**：Windows 会把成段的端口保留给 Hyper-V / WSL，落在保留段内的端口任何进程都无法绑定。

**处理**：

```powershell
## 查看当前保留端口段
netsh interface ipv4 show excludedportrange protocol=tcp

## 用仓库自带的前置检查脚本，自动判断 .env 中的端口是否可用
powershell -NoProfile -File scripts\preflight.ps1 -Ports 80,7000,18050,13307,6380 -Names frontend,backend,fastapi,mysql,redis
```

把 `.env` 中冲突的 `*_PORT` 改到保留段之外再重启即可
（本项目 MySQL 已因此从 3307 改用 13307）。

### 11. 安全基线（生产部署必读）

- [ ] `.env` 使用强随机密码与 32 字节以上 JWT 密钥，且不提交版本库

### 12. CI/CD 建议（后续演进）

当前实现"本地构建 + compose 启动"，已满足组员协作。更进一步的企业化方向：

1. **镜像仓库**：GitHub Actions / GitLab CI 在推送时构建并推送 `synpharm/backend|fastapi|frontend:<tag>` 到仓库；
2. **组员拉取**：`docker compose pull` 即可，无需本地构建（避免版本漂移）；
3. **环境分层**：`docker-compose.override.yml`（开发热重载）与生产 compose 分离；
4. **编排升级**：规模扩大后迁移 Kubernetes（现有 `deploy/` 可演进为 `deploy/k8s/`）。
